# doc-extract-filter 一句话启动手册（quickstart）

> 触发后：文档集先机械合并成纯母本 → 展示完整流程「⓿ 前置 + 7 大步/小步」清单 → 遍历清单逐项列出全部需用户回答的问题，用 AskUserQuestion 分多回问齐（含 Q0 与主问，不预设问题总数）→ 按 §3 命令序列跑完 → 不再问任何问题。
> 全程默认串行 1、前台；并发数由 Q4 用户自定、不设上限、不钳制，CPU 档位只给建议值；开多个 agent 须先经用户允许；429 为云端配额次要风险、非本机主判据。所有参数对齐 `scripts/run_pipeline.py` 真实接口；不确定处标 `(待核)`。
> 当前 WorkBuddy 支持询问，主路径按支持执行；若环境不支持询问，把全部问题一次性以文本列出后返回「任务完成」，不擅自往下跑。

## 0. 一句话触发

| 用户说法 | 进入模式 |
|---|---|---|
| 「把这份文档合并压缩并筛选」「跑一遍」「照旧」「按上次的流程」「一句话跑完」「开始」 | 全流程（默认） |
| 「只做筛选 / 只筛一下 / 这已经是合并稿」 | 仅筛选 |
| 「只合并压缩 / 只要合并结果」 | 仅合并 |
| 「从这几份源文档开始总结」 | 完整总结链 |

**铁律（用户红线）**：触发后**只允许在开场阶段提问**——用 `AskUserQuestion` **分多回**把 §2 的**全部问题**（遍历流程清单逐项列出，不预设总数）逐条问齐；**问齐即锁定，之后绝不再问**（无人值守前置、之后别问）。用户答「默认 / 照旧 / 你看着办 / 按上次」→ 全部取推荐默认值，直接开跑。

## 1. 意图路由表

> **先跑路由脚本，别临场猜**：`python scripts/route.py --text "<用户原话>" --source "<SOURCE>" --workdir "<WORKDIR>"`（**路径占位符一律加双引号**，中文/空格路径才不会被 shell 拆词）
> 输出建议模式、命中关键词、可复制的 `init` 命令、`--subject` 提示；加 `--json` 得结构化结果。
> 命中多模式或完全没命中会标 `ambiguous` / `ask_user`，此时**开场询问包 Q1 必须与用户确认**，不替用户拍板。
> 规则表在 `scripts/route.py` 的 `RULES`（含排除词，如「合并压缩并筛选」不会被误判成「仅合并」）。

| 用户说 | 模式 | init 关键参数 |
|---|---|---|
| 只做内容筛选（输入已是合并稿） | 仅筛选 | `--skip-merge`（S2 跳过，merged=`<SOURCE>`） |
| 只做条目合并压缩 | 仅合并 | **`--screening off`**（跳过 S3–S7 三道筛选链，不会停在 S4）+ 可选 `--volumes 0` 不分卷 |
| 合并+筛选全流程 | 全流程 | 默认（不带任何可选参数即全默认） |
| 从多份源文档开始（机械拼接+切块+逐块总结） | 完整总结链 | 先 `merge_and_chunk.py --inputs ...`，再把产物作 `--source` 入链 |

- **默认（用户没说清）**：全流程 = `--mode 合并+筛选 --zero-loss 硬数据零丢失 --delivery 7卷+定稿+行映射+三份筛选文档 --execution 严格串行前台 --volumes 7`，即 `init` 只带 `--source` + `--workdir`。
- **短路模式**：`--screening off` 让筛选链 S3–S6 全部 `skipped`，直接以筛选基准稿进入合并/分卷（合并现在在筛选之后）；S2 按空剔除集落盘、S7 出定稿、S8 分卷、S9 报告照常跑，`verify` 相应跳过三道集合与剔除行体检，只验指纹与分卷拼接。
- **完整总结链（前置链，已工具化）**：输入是多份源文档时，`run_pipeline.py` 不直接处理，先跑：
  ```bash
  # 1) 多源机械拼接 + 切块
  python scripts/merge_and_chunk.py --inputs a.md b.md c.md --out <切块目录>
  # 2) 逐块覆盖检查 → 生成某块的提示词 → 串行前台派 agent 写摘要 → 只追加
  python scripts/build_extract.py check    --chunks <切块目录> --extract <总提取稿.md>
  python scripts/build_extract.py template --chunks <切块目录> --extract <总提取稿.md> --index 1
  python scripts/build_extract.py append   --chunks <切块目录> --extract <总提取稿.md> --index 1 --summary <块摘要.md>
  # 3) 全部块齐备后取入链命令，把总提取稿作 --source
  python scripts/build_extract.py check    --chunks <切块目录> --extract <总提取稿.md> --finalize
  ```
  `build_extract.py` 严格 append（绝不覆盖已有内容、带防重复写入保护）、块号连续校验、
  `# === 来自 chunk_NNN ===` 硬边界、`<!-- BLOCK-DONE: N -->` 完成标记、
  逐块子 Agent 提示词模板（只追加/数字零遗漏/`[来源]` 用原稿名/**只回一行确认**）。
  **逐块总结本身仍由主线程串行前台派 agent 完成**（脚本不调模型，避免块内容回流主线程）。
  **机械步骤合并为单次命令（性能纪律）**：逐块 `template` / `append` 必须写成一次 `for` 循环或批量参数，前置探路（`--help` / `wc -l`）也合并成一条命令，**禁止一个块一次 CLI 调用**；完整纪律与理由见 `guide/tools-ops.md`「故障速查与执行纪律」。可照抄：
  ```bash
  # 单次工具调用：一次 for 循环生成全部块提示词
  for i in $(seq 1 18); do
    python scripts/build_extract.py template --chunks "<切块目录>" --extract "<总提取稿.md>" --index "$i"
  done
  # 单次工具调用：一次 append --all 把全部 summary_NNN.md 升序追加落盘
  python scripts/build_extract.py append --chunks "<切块目录>" --extract "<总提取稿.md>" --all
  ```
- **零散内容块自动探测（默认开，硬性）**：`line_select_merge.py` 未指定 `--scatter-marker` 时会自动识别「本块全条同源 / 仅标此一次 / 零散内容」类标题行并划为 AUTH 全保。实测漏分区会丢失大量独有纯文字概念，**而数字指纹仍显示零丢失**。`--no-auto-scatter` 可关闭；运行时务必核对打印的「零散起点：L…」，显示「未分区」且源文档有成片独有内容时必须显式指定 marker 重跑。
- `--no-builtin-rules`（更激进删重述）/ `--scatter-marker` 属「仅合并/自定义」可选微调，默认关/自动探测。
- **短文档真短路**：源 < 4 万字符时 `init` 自动 `screening=off` / `volumes=0`（`auto_shortcut=true`），跳过筛选链(S3–S6)与分卷，直接以筛选基准稿进入合并/分卷（合并现在在筛选之后）；想强制走完整链就显式 `--screening on --volumes 7`。成本预估里标 `短文档短路: true`。

## 2. 开场询问模板（分多回问齐）（遍历流程清单逐项列出全部问题，最重要）

用 **AskUserQuestion 在开场阶段连续分多回调用**遍历完整流程清单逐项列出并**分多回问完全部问题**（**平台单次上限：最多 4 题、每题最多 4 选项**，已知实测；每回按上限装题，**不预设回数、不预设问题总数**，直到 Q0~Q8 与全部补充决策项逐条问齐）；**主问（Q0 开场第一问 + 步骤选择——原 Q1/Q2——与 Q3~Q7）与全部补充项按回分配、连续多回逐条问齐**，**多回之间不得开始执行流程（不跑 `init`、不切块、不派 agent）**，用户未答即取默认。**所有决策问题必须逐条问到**（Q0~Q8 与全部补充项一律逐条弹窗问到、不得因有推荐默认值而省略）；**问齐即锁定开场询问包，问完之后绝不再问：任何阶段、任何问题都不再问（含决策项与技术项），流程中途禁止再回头问用户**。用户答「默认 / 照旧 / 你看着办」→ 全部取默认、直接开跑。

> 完整流程的「⓿ 前置 + 7 大步 / 小步」清单见 `SKILL.md` 第 0 节「完整总结流程清单」，问用户之前必须先展示。文档集先按 `SKILL.md` 第 0 节「输入与文档集合并」机械合并成纯母本，再展示清单、再问。

**Q0 模型跑在哪（开场第一问，单选）** → `init --model-host cloud|local`

问题集 = 主问（Q0 开场第一问 + 步骤选择——原 Q1/Q2——与 Q3~Q7）+ **遍历流程清单得到的各步骤补充问题**；**全部问题在开场阶段分多回问齐，不写死回数与问题总数**。

| 选项 | 含义 | 判据 |
|---|---|---|
| ① 云端 API／非本地（推荐默认） | 推理在云端，本机只做调度与文本 IO | **并发按 CPU 档位估，不看可用内存** |
| ② 本地模型 | 推理在本机，受内存/显存约束 | 看 GPU/NPU 性能 + 问急不急 → 定思考强度 |

**选①云端**：用一条轻量命令取 CPU 型号/核线程/标称频率即可粗分档，**不必跑基准测试**：`Get-CimInstance Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors`。

| 档 | 判据 | 默认 |
|---|---|---|
| 弱 | 4C8T 低压 U（示例机型，仅作档位说明） | 串行 1 |
| 中 | 8C16T 标压及以上 | 串行 1 |
| 强 | 更多核/更高频的桌面或工作站 | 串行 1 |

- 重文本任务（输入 >100KB、逐行判定、大量输出）建议串行 1，并拆小块 ≤160 行 / 预览 ≤30KB；并发数仍由 Q4 用户自定、不设上限。
- CPU 档位由 `init --cpu-tier weak/mid/strong` 接收（默认 weak），仅用于给并发建议值；不设上限、不钳制。
- 429 只是**云端配额的次要风险**，不得当本机并发主判据。

**选②本地**：同批追加问 GPU（或未来 NPU）型号与显存/算力（`Get-CimInstance Win32_VideoController | Select-Object Name, AdapterRAM`；NPU 暂无标准查询手段让用户自填 → `init --accelerator`）与**急不急**（不急／一般／很急 → `init --urgent`），据此定思考强度：

| 强度 | 触发 | 落地行为 |
|---|---|---|
| low | 不急 或 GPU/NPU 弱 | 串行 1、小块、提示词要求「只给结论、不展开推理、只回一行确认」、禁并发 |
| medium | 一般 | 默认；保持现有逐块总结行为 |
| high | 很急 且 GPU/NPU 能力足够 | 允许展开推理、可在用户授权下提高并发与块大小 |

`init --think-depth low/medium/high`（默认 medium，按 `--urgent` 与 GPU/NPU 信息给建议值）写入 `pipeline_state.json`；`pipeline_templates.py` 的 `render_agent_prompt()` 按 `think_depth` 追加一行强度指令；`run_pipeline.py init` 打印本次采用的 CPU 档 / 模型宿主 / 思考强度。

**Q1/Q2 本次执行哪些步骤（多选 · 列出全部步骤 · 带全选）** → `init --big-steps`（逗号分隔**新 7 大步**编号 1..7：1 切块总结 / 2 条目筛选 / 3 条目合并 / 4 终稿生成 / 5 检查 / 6 全文检查 / 7 达标判定与复压；支持任意子集如 `1,4,7`）/ `--small-steps`（逗号分隔小步编号如 `1.1,3.2,5.3`，取整数部分激活对应大步；两者留空/不传 = 全部）。⓿ 前置不计入编号、永远执行。

> 开场**必须先把 SKILL.md 第 0 节那张「⓿ 前置 + 7 大步 + 各小步（1.1~7.x）」完整清单展示给用户**，再问执行哪些；不要直接用「全流程/仅合并/仅筛选」预设分组糊弄过去——用户要从这棵树上**逐项勾选**。

**AskUserQuestion · multiSelect（两题，因平台单题上限 4 项；单回装满则顺延下一回）**：

| 题 | 选项（multiSelect 勾选） |
|---|---|
| **Q1 前期大步** | ① 第 1 步 切块总结 ② 第 2 步 条目筛选 ③ 第 3 步 条目合并 ④ 第 4 步 终稿生成（4 项全勾 = 前期全选） |
| **Q2 后期大步** | ① 第 5 步 检查 ② 第 6 步 全文检查 ③ 第 7 步 达标判定与复压 ④ 全选（＝Q1+Q2 全部 7 步，全流程） |

- **全选（全流程）** = Q1 + Q2 **全部勾选** → 不带 `--big-steps`/`--small-steps`（7 大步 + ⓿ 前置全跑，推荐默认）；任一组全勾即该组全选，Q2 勾「全选」即全流程全选。
- **自定义精确小步**：在「其他」框填小步编号（如 `1.1,3.2,5.3`）或大步子集（如 `1,4,7`）；用户可在两组任意组合（如只勾 Q1 ①④ + Q2 ⑦）。勾选合并后写 `--big-steps "1,4,7"`；只填小步编号写 `--small-steps`，脚本取整数部分激活对应大步。

> **粒度诚实说明**：执行按**大步级**；选 `3.2` 这类小步编号会激活对应大步 3 并跑其全部小步（小步间有依赖、不可独立跳过：去重依赖合并、三道筛选依赖判定基准）。「只跑某大步个别小步」暂不支持。`run_pipeline.py` 的 `skip_stages_from_answers` 真实消费这两个参数（支持任意大步子集组合），未选中大步置 `skipped`，不是空问；选第 5/6/7 步却没选第 3/4 步时给可读依赖告警、不崩。
> 既有三种模式（全流程 / 仅合并 `--screening off` / 仅筛选 `--skip-merge`）与 `--mode` 记录性参数全部保留、用法不变。
> **执行顺序已按权威流程真反转：筛选(第2步) → 合并(第3步)**：编排器 STAGES 真实执行顺序 = S1(指纹) → S3/S4/S5/S6(筛选链) → S2(条目合并，吃筛选结果落盘) → S7(终稿) → S8(分卷) → S9(报告)；三道筛选的行号基准统一为筛选基准稿，详见 `guide/red-lines.md`「当前实现边界」。


**Q3 模型上下文多少（用户输入）** → `init --context-cap`

问题文案必须带提示「**WorkBuddy 中可点击输入框右下角的圆环查看**」；请用户填减去系统提示词后的可用字符/token 数（整数）。

| 项 | 落地 |
|---|---|---|
| 影响 | 写入 `pipeline_state.json` 的 options/answers；成本预估新增按上下文的预计块数；未显式给 `--volumes` 时按上下文推导分卷数（钉在 1~20） |
| 既有 | `--context-cap` 也是 `split_document.py` / `merge_and_chunk.py` 切块时单块上限参数，口径一致 |

**Q4 每次可以并行多少 agent（选项 + 允许用户自己输入）** → `init --parallel`

问题文案**并发数由用户自己输入、不设上限、不钳制**；`--cpu-tier` 与 Q0 只用于给推荐默认值，不写死。选项：① 串行 1（推荐默认）② 自己输入任意数量。开多个 agent 须先经用户允许；重文本任务建议串行 1；429 为云端配额次要风险、非本机主判据。

| 选项 | 映射 |
|---|---|---|
| 串行 1（推荐默认） | `--parallel 1`（不传亦为 1） |
| 2 · 轻量任务（可选） | `--parallel 2 --cpu-tier weak`；按用户值写入 state |
| 自己输入任意数量 | `--parallel <N>` + `--cpu-tier weak/mid/strong`；并发数按用户值写入 state，不钳制、不设上限 |

**Q5 目标压缩体积（选项 + 允许用户自己输入）** → `init --target-compression`

问题文案期望输出压到多大；最终停止以零丢失硬底线为准，禁止为凑篇幅强压。选项：① 标准全面总结（推荐默认）② 尽量精简（压到原文 20%~40%）③ 详尽保留（几乎不压，仅去重合并）④ 自定义（填目标字符数或压缩比，如 `8000` 或 `30`）。

| 选项 | 映射 |
|---|---|
| 标准全面总结（推荐默认） | `--target-compression standard`（不传亦为 standard） |
| 尽量精简 | `--target-compression aggressive` |
| 详尽保留 | `--target-compression verbatim` |
| 自定义目标 | `--target-compression 30`（百分比）或 `--target-compression 8000`（目标字符数） |

**Q6 最大可容忍文档大小（选项 + 允许用户自己输入）** → `init --max-doc-size`

问题文案单份源文档超过多大时怎么处理；超过阈值仅告警+建议，不强制阻断。选项：① 自动判断（推荐默认，<4万字符短路、超大自动先分卷）② 指定上限（填字符阈值，如 `50000000` 约 50MB，超过先拆分/分卷再跑）③ 不限（超大也直接跑）。

| 选项 | 映射 |
|---|---|
| 自动判断（推荐默认） | `--max-doc-size 0`（不传亦为 0=不限） |
| 指定上限 | `--max-doc-size <字符数>`（如 50000000） |
| 不限 | `--max-doc-size 0` |

**Q7 压不到目标大小怎么办（选项 + 允许用户自己输入）** → `init --compress-policy`

当整轮产出后仍达不到 Q5 目标体积时如何处理；最终停止仍以零丢失硬底线为准，禁止为凑篇幅强压。选项：① 自动多轮复压（推荐默认，达零丢失下限仍压不到则停止并交付当前最佳）② 复压但按开场已固化的 Q7 决策执行、不再中途询问（达零丢失下限仍压不到时停止并交付当前最佳；「问完绝不再问」是硬规则，标注为已知限制，不实际回头问）③ 只跑一轮不复压。复压机制（回流统一规则）：不达标 → **回跳到第 3 步条目合并，把上一轮输出当输入接着跑**（允许逐条简化、不碰红线），直到达标或达零丢失下限；第 5 步补漏回流同样回跳条目合并；绝不写成「先合并后筛选再来一轮」的旧口径；`--max-recompress <轮数>` 控制最大轮数（默认 5）。

| 选项 | 映射 |
|---|---|
| 自动多轮复压（推荐默认） | `--compress-policy auto-stop --max-recompress 5` |
| 复压但压不到回头问 | `--compress-policy ask` |
| 只跑一轮不复压 | `--compress-policy single` |

**Q8 这份总结要保留哪些内容 / 用来做什么（筛选目标，开场必问）** → `init --goal`

## 3b. 新 7 步「第 5 步检查 / 第 6 步全文检查」可复制提示词要点

> 这两步目前是**流程定义与编排器挂载点**（见 `guide/red-lines.md`「当前实现边界」），完整语义实现待补，不宣称已实现。
> 硬红线：这两步若切块，块同样必须严格 < 模型上下文的 1/2；第 5 步重切块固定以 1/2 为上限（`--check-rechunk-cap`，默认取 `--context-cap/2`）。

**第 5 步 · 检查**（先脚本硬校验，再重切块 + 派 agent 补遗漏）：

```text
第一步（程序化硬校验，脚本跑、不占 agent）：
  python scripts/verify_three_pass.py --a ... --b ... --c ... --source ... --final ...
  python scripts/fingerprint.py --check ...        # 集合/数字指纹/逐行去向/零丢失证据
第二步（把输入文档重新切块，块 < 上下文 1/2，固定用 1/2 为上限）：
  python scripts/merge_and_chunk.py --file "<输入文档>" --context-cap <1/2上限> --out "<重切块目录>"
第三步（派前台 agent 补遗漏，给 agent 的话）：
  「完整读完 <重切块目录> 下每一块与 <当前总结稿>，逐块对照输入文档，
    找出总结里漏掉的信息（事实/数字/决策/流程/要点）并补回；只补遗漏、不删已有内容，
    块内容零回流主线程，完成后只回一行确认。」（强锁 1 个 agent 串行，跑完再起下一个）
```

**第 6 步 · 全文检查**（遍历最终输出做最后修改；上下文不足可切块检查）：

```text
「完整遍历 <最终输出> 做最后修改：核对来源标注、覆盖度自评、逐行去向映射、
  冲突裁决留痕、数字与要点可溯源；只改措辞/位置/补标，绝不删信息、不碰红线。
  上下文不足时把最终输出切块检查（块严格 < 上下文 1/2，--full-check-chunk-size 记录），
  逐块检查完再整体复核；后台 agent 一律禁用，强锁 1 个前台 agent 串行。」
```

**回流统一规则**：第 5 步补遗漏、第 7 步体积不达标，都**回跳到第 3 步条目合并，把上一轮输出当输入接着跑**（允许逐条简化、不碰红线），不写成「先合并后筛选再来一轮」。

## 3c. 第 3 步条目合并·真语义合并（命令序列 / 参数 / 提示词位置 / resume）

> `--semantic-merge on`（`init` 默认）时，S2 在筛选之后执行「按筛选结果落盘 + 真语义合并」；
> 脚本（`scripts/merge_semantic.py`）只做候选簇生成、硬校验、渲染，**不调模型**，语义裁决只由
> **1 个前台 agent**（强锁 1、并发 1、跑完再起下一个、不启动其他 agent）完成。
> `--semantic-merge off` 退回第一批直通（零改写，兼容）；`--legacy-merge` 走机械删行/去重。

参数（`init` 时固化进 `pipeline_state.json`）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `--semantic-merge on\|off` | `on` | 第 3 步真语义合并开关；`off` 退回直通 |
| `--similarity` | `0.80` | 候选簇相似度阈值（`difflib.SequenceMatcher` + 词元 Jaccard + 共享硬数据信号取较大） |
| `--max-cluster` | `20` | 单簇最大成员数 |

命令序列（`run` 停在 S2 后）：

```bash
# 1) run：S1 指纹 → S3/S4/S5/S6 筛选链（S4 停，派三道筛选 agent）→ resume 后到 S2
python "$PIPELINE" run --workdir "<WORKDIR>"
#    S2 会先生成候选簇 + 提示词，然后打印「停在第 3 步语义合并（S2）」并停下：
#    候选簇 = files["合并_候选簇"]、提示词 = files["合并_agent_prompt"]、
#    结果 = files["合并结果"]（均落「第3步 条目合并」步骤文件夹，可从 pipeline_state.json 的 files 读）
python "$PIPELINE" status --workdir "<WORKDIR>"   # 看 S2 waiting 与提示词/结果路径

# 2) 派 1 个前台 agent：完整读完 <合并_agent_prompt.md>、严格照做、
#    只写自己的 <合并结果.json>、完成后只回一行确认（结构见下方 JSON）。强锁 1、不并发、不启动其他 agent。

# 3) 产出后 resume：S2 自动 verify + render 硬校验，通过才把合并稿写入 f["merged"]，继续 S7–S9
python "$PIPELINE" resume --workdir "<WORKDIR>"
python "$PIPELINE" verify --workdir "<WORKDIR>"
```

`合并结果.json` 结构（agent 唯一允许写的文件）：

```json
{"items":[{"text":"合并或保留后的该条文本","sources":[原行号,...],"reason":"合并/保留依据"}]}
```

- 每个原始物理行号**恰好被覆盖一次**（不遗漏、不重复引用）；未入簇行各自作为独立 item（全覆盖）。
- 硬校验（`scripts/merge_semantic.py verify` 与 `render` 共用）：全覆盖／无重复引用／行号合法升序／
  `reason` 非空／数字·编号·单位指纹零丢失／不得凭空新增硬数据（严格只追加语义）；
  冲突多值全留并标 `【冲突：源稿矛盾】`、文档外推论标「（AI 推论）」。失败一律非零退出、明确报错、不落盘。
- 产物：`合并_覆盖校验.md`（逐行去向映射/覆盖率/指纹差集/被压缩行清单）、
  `合并稿.md`（= `f["merged"]` 供 S7 出终稿）、`合并_行映射.md`（逐行去向映射，输出文档之外单独存放）。

独立调用（不经过编排器，端到端实测用）：

```bash
python scripts/merge_semantic.py prepare --input 落盘稿.md --outdir 第3步文件夹 \
    --similarity 0.80 --max-cluster 20 --result 合并结果.json --workdir "<WORKDIR>"
python scripts/merge_semantic.py verify --input 落盘稿.md --result 合并结果.json \
    --fingerprint 基线.json --outdir 第3步文件夹
python scripts/merge_semantic.py render --input 落盘稿.md --result 合并结果.json \
    --fingerprint 基线.json --out 合并稿.md --map 合并_行映射.md
```

## 4. 三个串行 agent 的提示词模板（脚本自动生成，本节为原文与校验口径）

> **首选做法（§3 步骤 3/5/6）**：`run_pipeline.py` 的 S3 阶段已把三份提示词写成本工作目录下的
> `agent1_prompt.md` / `agent2_prompt.md` / `agent3_prompt.md`，路径、判定对象、基准、视图、母本、
> 输出 JSON 路径全部自动注入。主线程派 agent 时**只需让它完整读完对应提示词文件并照做**，
> 不必复制粘贴本节内容、也不必手工拼路径。模板源码在 `scripts/pipeline_templates.py`
> （`render_agent_prompt` / `render_criterion`），判定基准五节结构由 `render_criterion` 生成。
> 本节保留模板原文，供人工审阅、定制（改 `--subject` / `--keep-categories` / `--criterion-note`）
> 或脚本不可用时的兜底。

三道**严格串行、前台、一次只 1 个**，跑完一道再起下一道；每道**只回一行确认**（如 `done N M`），正文/判定内容零回流主线程；**不得修改任何既有文件**，只写自己的 `agentN_result.json`。

**通用硬约束（三道都贴）**：

- 只输出「行号 + 理由」的 JSON，**不输出正文、不手工复写/缩略/截断原文**（原文由脚本按物理行号逐字节抽取）。
- 行号 = 母本物理行号（1-based），与判定视图 `L<n>|` 一一对应；`line` 唯一、严格升序、不越界；每条 `reason` 非空（写明依据判定基准哪一条）。
- 串行前台、并发=1、不启动其他 agent；不引入母本外信息；拿不准一律放回/不剔。
- 写入前自检：结构合法、行号唯一升序无越界、reason 非空；不通过不落盘。

**§4-1 第 1 道 · 宽松初筛**

```text
角色：三道筛选·第1道（宽松初筛）。
必读（完整读完再动手）：
  1) <WORKDIR>/筛选_判定基准.md —— 唯一共用标准，五节模板
  2) <WORKDIR>/筛选_判定视图.txt —— L行号| 首55字…尾20字，通读全量行
  3) 母本原文 <WORKDIR>/合并结果.txt（--skip-merge 时=<SOURCE>）—— 拿不准用 Read offset/limit 按行号回查完整原文，严禁凭截首臆断
输入依赖：母本全量（判定视图 + 可回查原文）。本道不依赖任何上一道文档。
阈值：宽松初筛，疑似无关就拎出，允许误伤（误伤由第2/3道捞回）。
  仅当一行同时满足基准第二节三条 + 边界不模糊才判初判无关；骨架/夹带主题信息的整行一律留。
输出：写 <WORKDIR>/agent1_result.json，UTF-8：
  {"items":[{"line":N,"reason":"…","verdict":"初判无关"}]}
硬约束：见「通用硬约束」。只做第1道，不越权。
回执：只回一行 done <本道条数> <母本行数>，不回正文。
```

**§4-2 第 2 道 · 极宽松抢救（仅输入文档 A）**

```text
角色：三道筛选·第2道（极宽松抢救）。
必读（完整读完再动手）：
  1) <WORKDIR>/筛选_判定基准.md —— 与第1道同一份，不许各判各的
  2) 上一道文档 A：<WORKDIR>/筛选1_初判无关条目.md —— 本道唯一输入范围
  3) 母本原文 <WORKDIR>/合并结果.txt —— 仅按 A 内行号回查「该行及其下方若干行」上下文，判断「是否统领下方成片设计」
输入依赖：**仅**文档 A；不重读母本全文、不引入 A 之外新条目；输出必须 B ⊆ A。
阈值：极宽松，任何关联线索（间接/素材/背景/工具/灵感/骨架行）一律捞出，宁可错捞不可漏。
输出：写 <WORKDIR>/agent2_result.json，UTF-8：
  {"items":[{"line":N,"reason":"…","verdict":"捞回"}]}   // N 必须来自 A
硬约束：见「通用硬约束」。只做第2道，不越权、不改 A。
回执：只回一行 done <本道条数> <A 条数>，不回正文。
```

**§4-3 第 3 道 · 终审（拿不准→放回，可否决前两道）**

```text
角色：三道筛选·第3道（终审）。
必读（完整读完再动手）：
  1) <WORKDIR>/筛选_判定基准.md —— 唯一共用标准
  2) 文档 A：<WORKDIR>/筛选1_初判无关条目.md
  3) 文档 B：<WORKDIR>/筛选2_复核关联条目.md
  4) 母本原文 <WORKDIR>/合并结果.txt + 判定视图 <WORKDIR>/筛选_判定视图.txt
输入依赖：文档 A + 文档 B；逐条独立回查母本原文，不沿用前两道结论，可否决前两道任一判别。
阈值：拿不准→放回（零丢失硬底线）。须覆盖 B 每一条并复核 A 剩余条目。
输出：写 <WORKDIR>/agent3_result.json，UTF-8：
  {
    "items":[{"line":N,"reason":"…","verdict":"放回|剔除"}],
    "summary":{
      "final_remove_lines":[...],   // 最终剔除行号集合
      "final_restore_lines":[...],  // 放回行号集合
      "review_remaining":"…"        // A 剩余条目复核结论
    }
  }
  约束：final_remove_lines 与 final_restore_lines 互斥，且并集恰为 A（=agent1 items 行号全集）；
        items 须覆盖 B 每行；字段名对齐 verify_three_pass.py（remove/restore 等价键亦可）。
硬约束：见「通用硬约束」。只做第3道，不越权。
回执：只回一行 done <剔除数> <放回数>，不回正文。
```

**主线程额外独立抽查（第 1 道后、第 2 道前，必做）**：第 2/3 道只能复核文档 A 内条目，第 1 道若漏拎「大块无关内容」（成片工程残留 / 来源文件名列表 / 行映射说明块）后两道**结构上救不回**。主线程用关键词/结构标记在母本扫一遍，发现漏拎即把行号**补进 agent1_result.json** 再继续（A 变大，第 2 道输入随之更新）。此抽查由主线程做，不新起 agent。

## 6. 自动验收清单

| 项 | 判据 | 落点 |
|---|---|---|
| 定稿字节一致 | `final == b"".join(筛选基准稿按行删去 remove 集)` | S7 断言；`verify` 的 `--final` 逐字节；`verify_final` |
| 三道集合互斥且并集=初判全集 | `remove ∪ restore == A` 且 `remove ∩ restore == ∅`；`B ⊆ A`；C.items 覆盖 B | S6 `verify_three_pass.py`（7 项；带 `--final` 为 8 项含定稿逐字节） |
| 三类指纹集合层 0 缺失 | `set(base)-set(out)==∅`（种类覆盖，非计数） | `fingerprint.py --check --exclude-noise`（S6 / verify） |
| 分卷拼接逐字节相等 | `b"".join(vols) == final` | S8 断言 + `verify` 分卷项 |
| **剔除行内容体检** | 终审剔除集中「含文字的行」= 0 则 PASS；>0 则 `WARN` 并落 `剔除行内容体检.md` 供人工复核（防纯文字设计条目被误删——数字指纹查不出这类丢失） | S7 自动落盘；`verify` 独立补做并刷新报告；报告「四、自动验收」段 |
| **零散内容块分区** | 新链默认：S2 按筛选结果整行落盘、不做机械删行 → 零散分区不适用；仅 `--legacy-merge` 开启时才按 `scatter_info.enabled=True` 核对「零散起点：L…」（`--no-auto-scatter` 关闭） | S2（`--legacy-merge` 可选，默认关）；报告「三·补」段 |
| **三条零丢失证据齐备** | ①数字指纹集合层 0 缺失 ②剔除行内容体检 PASS/人工确认 ③零散块分区核对通过。**「指纹零丢失」不等于「内容零丢失」**，缺任一条不得宣称零丢失 | S2 + S7 + `verify` + 运行报告 |
| 行映射覆盖 | 输入 L1–L末全覆盖、无 `输出LNone`、映射在输出文档之外 | S7 `筛选_行映射.md`、S2 `合并_行映射.md` |
| 设计条目 0 删 | 剔除仅限纯空白/纯工程残留 | 三道判定基准 + 运行报告说明 |

- `verify` 命令 = 独立全量验收：三道集合+定稿字节（`--final`）+ 三类指纹 + 分卷拼接，打印 `=== 验收总结果：PASS/FAIL ===`，FAIL 则 exit 1 禁止交付。
- `运行报告.md` 的「**四、自动验收**」段 = 清单式 6 项（定稿存在/字节>0/三份筛选文档齐全/行映射存在/三份 agent JSON 齐全/分卷拼接==定稿），由 `report` 刷新；样例见工作目录下的 `运行报告.md`。

## 7. 断点续跑与故障恢复

- **先诊断**：`python "$PIPELINE" doctor --workdir "<WORKDIR>"` 自动逐阶段核对产物，输出缺失项 / 可能原因 / 建议命令；会按 `--skip-merge`、`--screening off` 排除不适用产物，不误报。
- 运行报告开头的**交付摘要卡**可直接读：模式、源→定稿字节、三道统计、三条零丢失证据、自动验收结论，不必翻长报告。
- 任何阶段中断：`python "$PIPELINE" status --workdir "<WORKDIR>"` 看进度与下一步（细分到「派第几道 / 先 prepare / 可 resume」）→ `python "$PIPELINE" resume --workdir "<WORKDIR>"` 从首个非 done 阶段续跑（已 done 阶段自动跳过）。
- agent 被中断：**先查残留** `agentN_result.json` 是否存在/合法/行数合理，再判「已产出/部分产出/零产出」；只补缺失区间、不整批重跑，重跑加防重复写入保护。
- **后台 agent 在本环境必被回收、零产出 → 三道一律前台串行**，不再重试后台（troubleshooting C16）。
- 框架报 `failed` / 超时 / 429 → **先查文件系统**（`ls` / `wc -l` / 查输出文件是否已写完）再下结论，实测有「failed 但文件已完整写完」零成本复活（C17 / E 判定树）。
- 常见故障速查（详见 `references/troubleshooting.md`）：
  - SIGTERM 超时死循环 → B7（状态常量 `'DEL'`/`'DEL_REDUNDANT'` 不一致）
  - CRLF 假字节差、拼接还原失败 → A1（一律 `rb`/`wb` + `splitlines(keepends=True)`）
  - 多重集假丢失 → B8（改集合层 `set`，不用 `Counter`）
  - 429 限流 → C15（严格串行、TaskStop 多余 agent、窗口内停手）
  - 骨架误删 / 来源标记当残留 → D21（基准写死骨架保留、边界模糊不剔）
- **已达零丢失下限必须停止压缩并向用户报告**「已达零丢失下限，继续压必然丢数据」，**禁止强压**（zero-loss-merge.md §6 / guide/red-lines.md 红线 18；双阈值：压缩比≥0.9 / 输出≥输入 / 连续 N 轮无下降）。

# 终稿格式模板（output-template）

> 定位：text-summary-filter **标准总结主流程**收尾时的终稿落盘骨架。所有终稿合并 agent 共用同一套模板，guide/tools-ops.md「交付与清理」节只写了命名 / 格式 / 清理顺序，未给骨架，本文件补齐。
> 配套：`markup-protocol.md`（标记协议与 agent 铁律）、`troubleshooting.md`（来源定位技巧）、`three-pass-screening.md`（按行筛选，另一条链）。
> 红线：先落终稿并校验、再谈清理；原文零改写（默认保真手段，目标为信息不丢）、文档内信息只改位置不删；来源必须标明；文档外推论显式区分。
> 本文只给可套用模板与硬约束，不复述实战对话、不堆理论。

---

## 1. 完整终稿 txt 模板（可直接套用）

以下为**终稿正文骨架**，占位符 `《X》` / `块N` / `X/Y` 按实填写。整份是纯 txt：不含标题井号、加粗星号、行内代码反引号；保留减号起始符与表格竖线结构。

```text
《X》·总结
本总结全部内容提炼自《X》，不含文档外信息；按文档块序归纳，逐条标注「块N」以便溯源。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

一、元总结（全局摘要，10~14 条编号要点）
1. ……【块 N】
2. ……
……
14. ……

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

二、逐块要点（按原文顺序，每条标【块 N】）
【块 1】[来源：原始稿文件名]
- ……
- ……
【块 2】[来源：原始稿文件名]
- ……
……

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

三、去重与校验说明
- 完全重复：删冗余、指回前文「同上 / 见 X 节」，不重写。
- 大致重复：互补或各带不同信息者全部保留，不删任何一个。
- 冲突裁决：保留前 / 保留后 / 都保留 / 自定义，批量一次问完；同字段多值全保留并标【冲突：源稿矛盾】。
- 数字指纹：原文全量抽取与终稿做集合比对（种类覆盖，非计数），差集逐个补回，补完才允许交付。
- 覆盖完整性：结构清单逐条核对，每个核心子系统须有规则级落点；分散碎片已合并成独立模块条目。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

四、关键数值补录（按子系统分组）
【子系统 A】
- 参数 / 阈值 / 配比 / 百分比 / 时长 / 尺寸 / 坐标 / 版本号 / 公式系数：……[来源：原始稿文件名]
【子系统 B】
- ……

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

五、冲突处理记录
- J1：……两种说法全列，待用户裁决（保留前 / 保留后 / 都保留 / 自定义）。
- J3 ≡ J5：已并入 J3，不单列。
- ……（跨批次合并去重留痕，终稿汇总成「冲突总 registry」）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

覆盖度自评：结构清单 X/Y 条有规则级落点（「接XX大改」「详见XX」式裸引用不计覆盖）。
```

### 1.1 字段说明

| 段 | 写什么 | 硬约束 |
|---|---|---|
| 标题行 | 书名号包原文档名 + 「·总结」 | 与原文档名一致，不另起花名 |
| 第 2 行 | 来源声明原话 | 一字不改套用；须声明「不含文档外信息」 |
| 分隔线 | `━━━━` 段间硬分隔 | 纯符号行，属文档骨架，保留不剔 |
| 一、元总结 | 10~14 条编号要点，全局摘要 | 每条可带【块 N】溯源；不堆细节、不展开规则 |
| 二、逐块要点 | 按原文块序，每块一条起 | 每条必须标【块 N】，顺序即块序，不重排 |
| 三、去重与校验说明 | 三类去重 / 裁决 / 指纹 / 覆盖的处理留痕 | 只写「怎么处理的」，不重写被合并正文 |
| 四、关键数值补录 | 原文有、终稿无的数字按子系统分组 | 数字是规则可执行部分，一个不许丢 |
| 五、冲突处理记录 | 编号化 registry 全量 + 已并入留痕 | 同字段多值全保留，绝不取一丢一 |
| 末尾自评 | 「结构清单 X/Y 条有规则级落点」 | 让遗漏可量化、可复查 |

### 1.2 两个易错点

- **元总结不是压缩终点**：元总结按主题归类有两个系统性坑——核心子系统被压成「接XX大改」裸引用（规则层整层丢失）、完整功能模块因分散几十块归不进显性主题而整体蒸发。故「二、逐块要点」与「四、关键数值补录」必须与元总结并存，不能只留元总结。
- **附录 / 补遗回原位**：把补遗、数字回填移入对应块、结构盘点前置为目录，只改位置不删；附录须落回文末真实脚注之前，不插进正文第 5 行。

## 2. 格式硬约束

| 项 | 规定 |
|---|---|
| 默认格式 | 纯 txt（点 txt 文件） |
| 标点 | 全角中文标点；比对 / 抽取前先规整全角半角（全角百分号转半角、全角数字转半角） |
| 去 markdown 符号 | 删标题井号、加粗双星号、行内代码反引号三类标记；正文不出现 |
| 保留的符号 | 减号加空格的列表起始符、`【…】` 分组标记、`[来源：…]`、表格竖线结构、`━━━━` 分隔线——均属文档骨架，一律保留 |
| md | 仅在用户明确要求时保留；否则作为过程稿处理，不随终稿交付 |

说明：

- 「去 markdown 符号」只针对标题井号、加粗双星号、行内代码反引号三类，**不是**删掉所有结构符号。红线「文档骨架一律保留」与合并铁律「每条设计点单独成行、用【xxx】分段」优先。
- 表格保留竖线结构即可，不必补 markdown 表格语法的对齐分隔行（那是 md 才需要）。
- 终稿是给人读的纯文本，不是给渲染器读的 Markdown；章节标题一律写成「一、」「二、」中文编号。

## 3. 命名与落盘

| 项 | 规定 |
|---|---|
| 文件名 | 原文档文件名后加「总结」二字（`报告.txt` → `报告总结.txt`） |
| 位置 | 与输入文档**同一根目录** |
| 编码 | UTF-8；读文件先剥离 UTF-8 BOM |
| 二进制安全 | 移动 / 重命名（mv / Rename-Item）可能被安全策略拦截，用「读内容 → 写新文件」替代 |

### 3.1 交付顺序铁律（顺序不能反）

1. 先落终稿到同根目录。
2. 校验通过：**行数 / 大小 / 头部**（头部 = 标题行、第 2 行来源声明、`━━━━` 分隔线齐全且无 BOM / 乱码）。
3. 校验通过后才谈清理。终稿产出前，各级产物（chunks/、逐块摘要、分段输入、分段整理）必须保留，供追溯与补救。
4. 删除中间产物前在回复中**列明删了什么**（目录 / 文件数 / 大小），让用户可追溯。
5. 顺序反了等于把工果实拆了——**先删中间、后落终稿**是绝对禁止的。

### 3.2 交付闭环

- 终稿交付并校验后，主动询问用户是否做一次「二次检查」（对照原文逐条 / 逐主题核查遗漏，或针对指定段落补查），不沉默收尾。
- 中间产物默认保留、绝不主动删；用户本轮明确指示「删除过程文件」才删，错误版本移 `_bad/` 不删。

## 4. 来源标注规范

| 规则 | 说明 |
|---|---|
| 标注形式 | `[来源：原始稿文件名]`（半角方括号） |
| 绝不填 `chunk_xxx.txt` | 切块名是机械产物、不是来源；填了就失去文件名级溯源 |
| 同源只标一次 | 同一块 / 同一组条目同源稿，`[来源]` 只标一次，不逐行重复 |
| 开头声明 | 第 2 行统一声明「本总结全部内容提炼自《X》，不含文档外信息」 |
| 按块 / 章节注出处 | 「二、逐块要点」每条标【块 N】；元总结要点可带【块 N】 |

### 4.1 块缺来源硬边界标记时

机械拼接母本里每份源前本应有 `### 来源文件：<名> ###` 硬边界；若某块恰好缺该标记，按以下顺序定位：

1. 取块内**独有短语**（罕见设定名 / 数字组合 / 关键原话）。
2. 用该短语在母本（可达 9MB 级）Grep 定位到具体行。
3. 从命中行**向上找最近的来源标记**，以该标记里的原稿名填入 `[来源]`。
4. 仍定位不到才标 `[来源：待核]`，绝不猜一个 `chunk_xxx.txt` 顶替。

### 4.2 来源标签与零改写

- `[来源：…]` 属文档骨架，筛选 / 清洗阶段一律保留，不当工程残留剔除。
- 若本轮确需删除来源标签（会失去文件名级溯源），必须先备份 `.bak_来源` 并说明「行级溯源（行映射）仍在」。

## 5. 文档外推论显式标注

- 任何**不是原文陈述**、由总结方补出的推论 / 补充 / 点评，一律显式标「（AI 推论）」。
- 绝不与原文混写：不把推论塞进编号要点当原文事实，不借「可轻易读懂」为由替作者补解释。
- 原文没解释的设定，不擅自脑补世界观、机制或未说明的因果。
- 完整度 ≠ 冗余度：需解释才读懂的句子给必要说明，一眼自明的不画蛇添足；「漏没漏」与「啰不啰嗦」分开管。

## 6. 覆盖度自评与三重查漏的衔接

终稿末尾的「结构清单 X/Y 条有规则级落点」不是孤立一句话，它是三重查漏的**量化出口**。三者输入不同、落点不同，缺一不可：

| 查漏 | 基线 / 输入 | 防什么 | 落进终稿哪一段 |
|---|---|---|---|
| ① 主题比对（二次查漏） | 分段整理结果逐主题比对终稿 | 分段时漏掉的主题不会自己冒出来（曾漏 4 个整主题） | 一、元总结 / 二、逐块要点补回 |
| ② 结构清单基线 | 整理前盘点原文自称的子系统 / 功能模块 / 条款编号（如 aa~ct） | 防压扁（裸引用）+ 防蒸发（整模块不在任何主题里） | 四、关键数值补录（按子系统分组）+ 末尾覆盖度自评 |
| ③ 数字指纹比对 | 正则抽原文全量「数字 + 单位 / 范围」与终稿集合比对 | 数字是规则可执行部分，丢一个即失真 | 三、去重与校验说明（比对留痕）+ 四、关键数值补录（差集补回） |

衔接规则：

- **② 的 Y** = 结构清单条目总数，**X** = 其中有规则级落点（可执行参数 / 条件 / 公式 / 流程）的条数；「接XX大改」「详见XX」式裸引用不计入 X，要么展开写、要么明确标「原文即引用、无细则」。
- **③ 的口径**是种类覆盖非计数覆盖：原文重复出现的同一数字，终稿合并同类项不算漏；差集回原文定位后程序定性排除噪声（图片 CDN 哈希、auth_key、13 位时间戳、纯章节序号、大数字子串），再逐个补回。
- **① 的自查形态**：「自查 N 次」= 派 N 批 agent **真读原文、对照终稿、边读边查内容层面遗漏**，不是用程序扫数字（程序扫只算数字核验，查不出语义蒸发）；查前先问用户查几遍。
- 三道缺口全补齐、X/Y 量化写完，才允许进入「交付与清理」。

## 7. 交付前自检清单

| # | 检查项 | 通过判据 |
|---|---|---|
| 1 | 骨架齐全 | 标题行 / 第 2 行声明 / 分隔线 / 五个编号段 / 覆盖度自评，六件齐 |
| 2 | 第 2 行原话 | 与「本总结全部内容提炼自《X》，不含文档外信息；按文档块序归纳，逐条标注「块N」以便溯源」一致 |
| 3 | 块序与标记 | 二、逐块要点按块序、每条有【块 N】 |
| 4 | 格式 | 无标题井号 / 加粗星号 / 行内代码符；全角标点；表格竖线保留 |
| 5 | 来源 | `[来源：原始稿文件名]`，无 `chunk_xxx.txt`，同源只标一次 |
| 6 | 推论 | 所有非原文内容带「（AI 推论）」，无混写 |
| 7 | 数字 | 种类覆盖差集为 0；四、按子系统分组补录完毕 |
| 8 | 冲突 | 五、registry 全量 + 并入留痕；同字段多值全保留 |
| 9 | 落盘 | 文件名 = 原名 + 「总结」，与输入同根目录，UTF-8 无 BOM |
| 10 | 顺序 | 已先落终稿并校验（行数 / 大小 / 头部），再谈清理 |

> 本文件只描述**标准总结主流程**的终稿格式。`scripts/run_pipeline.py` 编排的是「文档总结条目合并 + 三道内容筛选」链，其产物（合并结果 / 三份筛选文档 / 分卷 / 行映射）另有规格，见 `references/quickstart.md` 与 `references/three-pass-screening.md`，与本模板不冲突。

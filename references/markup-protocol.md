# 标记协议 + 三类 agent 提示词铁律（markup-protocol）

> 定位：text-summary-filter **标准总结主流程**的标记协议与 agent 提示词铁律固化。SKILL.md 正文散落了「只回一行确认」「只追加」「冲突全留」等约束，但未给统一标记表与可复制提示词，本文件补齐。
> 配套：`output-template.md`（终稿骨架）、`three-pass-screening.md`（三道筛选，另一条链）、`quickstart.md`（pipeline 编排手册）。
> 红线：同字段多值全保留、来源绝不填切块名、块内容零回流主线程、原文零改写（默认保真手段，目标为信息不丢）、严格串行不并行。
> 本文只给协议表与可复制模板，不复述实战对话、不堆理论。

## 1. 标记协议表

| 标记 | 形式 | 用途与硬约束 |
|---|---|---|
| 废弃 | `【已废弃】` | 行首全角括号；确认已被后续设定取代者 |
| 废弃·疑似 | `【已废弃·疑似】` | 行首全角括号；疑似被取代但未确证，留待人工裁决 |
| 源稿矛盾 | `【冲突：源稿矛盾】` | 同字段多值**全部保留**并标注，绝不取一丢一、绝不二选一 |
| 另见说法 | `（冲突：另见…说）` | 行内圆括号，指向另一处口径，不改写正文 |
| 重叠区 | `⟦OVERLAP 来自块N尾部·重复区⟧ … ⟦OVERLAP 结束⟧` | 相邻块默认 1-4kb 重叠正文（可按文档信息密度升降档）；随块自包含，重复留到合并阶段统一去重 |
| 来源硬边界 | `### 来源文件：xxx ###` | 多源机械首尾拼接时每份前插的硬边界，仅作溯源锚点、不计入总结内容，**不加过渡润色** |
| 追加锚点 | `<!-- APPEND -->` | 追加写入哨兵；总文档只追加不覆盖、不读整份总文档 |
| 冲突编号 | `⚠️冲突` / `⚠️并存 N` / `J1–J18` | 编号化 conflict registry；早期用「并存1~N」、后续用「J1~N」 |
| 块标记 | `【块 N】` | 逐块要点溯源；终稿「二、逐块要点」每条必带 |
| 拼接块头 | `# === 来自 chunk_NNN ===` | 追加式抽取时每块写入总文档的块头（仅追加链内部使用） |
| 一行回执 | `done NNN M` | agent 只回一行确认，不回正文 |

### 1.1 废弃标记写法

- **一律行首全角括号统一**：`【已废弃】`、`【已废弃·疑似】` 放在整行最前，后面接原条目。
- **禁内联「废弃 / 否决」**：不许把「废弃」「否决」「作废」等字样散在句子中间当描述；判定与留痕只走行首标记。
- 拿不准是不是真废弃 → 用 `【已废弃·疑似】`，不直接删、不直接判死。

### 1.2 冲突标记与编号化 registry

- `【冲突：源稿矛盾】` 触发条件：同一字段在源稿里出现多个值（数字 / 结论 / 时间线打架）。**所有版本全列、全保留**，不自动取信息更全的一版、不取前不取后。
- 每个冲突给**持久编号**，跨批次合并去重：
  - 同一冲突在不同批次被重复登记时，写成 `J3≡J5`、`J4≡J10`、`J1≡J18`、`并存3≡J11`，视为一条只留一个主号。
  - 被并入处在另一处标「已并入 X，不单列」，保留演进留痕，不抹掉历史。
- 终稿「五、冲突处理记录」汇总成一份**「冲突总 registry」**：列出所有独立口径 + 已并入的演进留痕，交用户统一裁决（保留前 / 保留后 / 都保留 / 自定义）。
- 大致重复（互补或各带不同信息）不删、并存标记全保留，永不自动丢弃冲突。

### 1.3 来源与边界标记

- `### 来源文件：xxx ###`：机械首尾硬拼接，**不加过渡润色、零去重零总结**；它是锚点不是正文。
- `[来源：原始稿文件名]`：逐条来源标注，**绝不填 `chunk_xxx.txt`**；同源只标一次。与来源硬边界是两个不同标记，勿混用。
- 块缺来源硬边界时，用块内独有短语在母本定位、找最近来源标记（详见 `output-template.md` §4.1）。

### 1.4 标记示例（一段带全标记的追加稿）

```text
# === 来自 chunk_007 ===
【已废弃】旧版流体每 tick 更新 1 次（已被下方 4 次取代）
【已废弃·疑似】早期天气阈值 0.35（疑似与 v3 冲突表重复，待裁决）
【块 7】[来源：示例_流体与天气.txt]
- 流体每 tick 更新 4 次；扩散半径 3 格；黏度系数 0.82。
- 降雨概率 12%~18%【冲突：源稿矛盾】（冲突：另见第 3 章说 20%）
⟦OVERLAP 来自块6尾部·重复区⟧
- 水洼蒸发速率 0.5 格/秒（与块 6 尾部重复，留到合并阶段统一去重）
⟦OVERLAP 结束⟧
<!-- APPEND -->
```

示例要点：废弃标记在行首、冲突双值全留、来源填原稿名不填切块名、重叠区成对包裹且不提前去重、追加锚点在末尾。

## 2. 三类 agent 提示词铁律（标准总结主流程）

> 三类 = ① 逐块总结（生产）② 合并 / 压缩（收敛）③ 审查（保真 + 遗漏）。下列代码块可直接复制派发；尖括号内为占位符。
> 通用：严格串行、前台、并发 = 1；块 / 摘要正文任何时刻不回流主线程；只回一行确认；不修改任何既有文件，只写自己的专属输出。

### 2.1 逐块总结子 Agent（可复制）

```text
角色：文档总结子 Agent（上下文隔离，text-summary-filter 标准流程逐块总结，全局并发=1）。
上下文隔离：你是一个干净上下文，只接收本块文本，不共享历史、不引用其他块、不借助全局记忆；
            块内自带的 ⟦OVERLAP⟧ 重叠尾巴属本块内容。
输入：<本块文件路径>（只读这一块，含重叠尾巴）；输出：<指定输出路径>，UTF-8 markdown。
铁律：
  1. 只读本块，不读其他块、不回源稿、不读整份总文档。
  2. 高保真保留：关键设定 / 系统 / 模组清单 / 数字参数与阈值 / 决策与结论 / 风险点 / 流程
     ——数字一个不许漏（参数、阈值、百分比、坐标、编号、公式系数全留）。
  3. 剔除寒暄套话、客套填充、与目标无关的闲聊；其余文档内陈述都要有落点。
  4. 按主题组织，不按原文流水账复制；需解释才读懂的句子给必要说明，一眼自明的不画蛇添足。
  5. 只追加写指定 utf-8 路径，绝不覆盖、绝不中途删改 / 去重 / 裁决冲突。
  6. 严禁把块正文或摘要正文粘贴回主线程；块内容零回流。
回执：只回一行确认（如 done <块号> <条数>），不回正文、不复述块内容。
```

### 2.2 合并 / 压缩 agent 铁律（可复制）

```text
角色：合并 / 极简 / 二压 agent（标准总结主流程的收敛环节）。
输入：<本次要压的输入文件>；输出：<专属输出文件>（只写这一个，不读写共享文件）。
铁律：
  1. 只压输入，不回源稿、不自行添加任何源文档内容、不脑补设定。
  2. 保留全部硬数据，一个不许丢：数字 / 公式 / 阈值 / 坐标 / 版本号 / 配比 / 概率 /
     百分比 / 时长 / 格数 / 重量 / 字节计数 / 倍数。
  3. 同字段多值全保留并标【冲突：源稿矛盾】，绝不取一丢一。
  4. 同源 [来源：原始稿文件名] 只标一次，不逐条重复；绝不填 chunk_xxx.txt。
  5. 每条设计点单独一行、以减号加空格起始；用【xxx】做分段标记。
  6. 纯分隔行可删，但其 [来源] 必须并入相邻条目，不许随行丢失来源。
  7. 必须处理完全部输入，不得中途停、不得只交前半段（输入有几行就压几行）。
  8. 只写专属输出文件；不改写、不重写任何已有条目（原文零改写）。
统计：结束前打印三项——输入字节数 / 输出字节数 / 条数。
回执：只回一行确认，不回正文。
```

### 2.3 审查类 agent（两个模板，可复制）

**模板 A · 内容保真检查员**

```text
角色：内容保真检查员（自查 N 批之一，真读原文查语义遗漏）。
输入：<原始母本> + <终稿>；输出：<本批审查报告路径>。
铁律：
  1. 真读原文，对照终稿，边读边查内容层面的语义遗漏（不是程序扫数字）。
  2. 重点查：决策 / 拍板、系统运作逻辑、清单（模组 / 名单 / 条款）、约束条件、关键原话
     是否被压扁、被裸引用替代、或整块蒸发。
  3. 明确：不要只查数字——数字程序已单独核验（数字指纹比对另跑）。
  4. 分散在几十块、归不进显性主题的完整模块，重点确认有没有整体蒸发。
  5. 报缺失点须回原文 Grep 核实，不盲追幻觉漏项；只补真实缺失。
回执：只回一行确认（本批重要遗漏数 / 次要遗漏数），不回正文。
```

**模板 B · 遗漏审查员**

```text
角色：遗漏审查员（逐行核对，islice(f,a,b) 只读指定行区间）。
输入：源 <a..b> 行区间 + 对应输出段；输出：<本区间审查结论路径>。
方法：用 islice(f,a,b) 逐行核对——源每行设计点 / 硬数据是否在输出有对应。
允许：同义改写、省主语、同源 [来源] 只标一次、跨块合并。
不允许：硬数据丢改（数字 / 单位 / 编号一个不许变），设计点整条遗漏；
        同字段多值须两个值都在且标【冲突：源稿矛盾】。
严格输出（二选一，不写别的）：
  块N 全段无遗漏          /          块N 共 N 处遗漏（逐处列行号 + 缺失内容）
  重复: 是 / 否
回执：只回一行确认，不回正文。
```

### 2.4 「自查 N 次」的正确形态

- 「自查 N 次 / N 轮」= 派 **N 批 agent 真读原文、对照终稿、边读边查内容遗漏**，对应本节模板 A。
- **不是**用程序扫数字、也不是数字自检脚本那种数字脚本（程序扫只算数字核验，查不出语义蒸发）。
- 查前先问用户具体查几遍，再据此派批；低成本可先让外部 AI 端对话式自查一次，把缺失点贴回，我方再查一轮补入。
- 模板 B 是逐行硬核对（设计点 / 硬数据对应），模板 A 是语义层查漏，两者互补，不互相替代。

## 3. 铁律速查（合并 / 追加共用）

| # | 铁律 |
|---|---|
| 1 | 只追加、不覆盖；总文档用 append 模式，先写块头再逐条写 |
| 2 | 原文零改写：agent 只给行号 + 理由，原文由脚本按物理行号逐字节抽取 |
| 3 | 块内容零回流主线程：块原文与摘要正文任何时刻不进主记忆 |
| 4 | 只回一行确认：提示词写死，否则 agent 回吐全文撑爆上下文（400 prompt too long） |
| 5 | 派发最小信息：提示词只含「本块路径 + 输出路径 + 格式要求」，不带全局背景 |
| 6 | 严格串行、前台、并发 = 1；后台 agent 在本环境被回收零产出，不开 |
| 7 | 框架报 failed 先查文件系统再重跑；被中断先查残留 JSON 再补跑，只补缺失区间 |
| 8 | 每个 agent 认领独立区间、写独立文件，防写冲突；不读写共享文件 |
| 9 | 文档骨架一律保留：章节标题、`###` 小标题、`【…】` 标记、`- ` 起始符、来源标注、分隔区块 |
| 10 | 已达零丢失下限必须停止压缩并报告，禁止为凑篇幅强压 |

### 3.1 协议落地自检清单

| # | 检查项 | 通过判据 |
|---|---|---|
| 1 | 废弃标记 | 全在行首全角括号；无内联「废弃 / 否决」字样 |
| 2 | 冲突全留 | 同字段多值全列、都带【冲突：源稿矛盾】，无二选一 |
| 3 | 编号 registry | 每冲突有持久号；跨批次写 `J≡J`，已并入处留痕 |
| 4 | 来源 | `[来源：原始稿文件名]`，无 `chunk_xxx.txt`，同源只标一次 |
| 5 | 硬边界 | 机械拼接每份前有 `### 来源文件：xxx ###`，无过渡润色 |
| 6 | 重叠区 | `⟦OVERLAP …⟧` 成对、随块自包含，未提前去重 |
| 7 | 追加 | 只 append、`<!-- APPEND -->` 锚点在，绝不覆盖 / 读整份总文档 |
| 8 | 回执 | 每个 agent 只回一行 `done NNN M`，无正文回流 |
| 9 | 提示词 | 逐块 / 压缩 / 审查各用本文件对应模板，未与 S4 筛选模板混用 |
| 10 | 串行 | 前台、并发 = 1、未启动其他 agent，独立区间独立文件 |

## 4. 与 `scripts/run_pipeline.py` 三道筛选提示词的分工

| 项 | 本文件（markup-protocol.md） | `run_pipeline.py` 自动生成的三道筛选提示词 |
|---|---|---|
| 服务流程 | **标准总结主流程**（切块 → 逐块总结 → 合并 / 压缩 → 三重查漏 → 终稿） | 「文档总结条目合并 + 三道内容筛选」链（S4 语义阶段） |
| agent 角色 | 逐块总结 / 合并压缩 / 内容保真 / 遗漏审查 | 第 1 道宽松初筛 → 第 2 道极宽松抢救 → 第 3 道终审 |
| 输入 | 块文本 / 块摘要 / 母本 + 终稿 | 判定视图（行号 + 首 55 字…尾 20 字）+ 可回查母本 |
| 输出 | 块摘要 / 压缩稿 / 审查报告（写盘，回一行确认） | `agent1/2/3_result.json`（行号 + 理由 + verdict） |
| 判定对象 | 语义层：设定、数字、决策、流程是否被压扁或蒸发 | 行级：某行是否「毫无关联、可剔除」（拿不准→放回） |
| 原文处理 | 高保真保留 + 零改写 | 原文零改写，脚本按物理行号逐字节抽取 |

**两者不冲突**：

- 本文件的模板用于「把长文档总结成终稿」，pipeline 的提示词用于「把已合并母本按行剔除工程残留」。
- 两者共享底层红线（原文零改写、只回一行确认、严格串行、骨架保留、拿不准→放回 / 留全），但**提示词不互相套用**：不要拿三道筛选的行号 JSON 模板去派逐块总结 agent，也不要拿本文件的压缩铁律去跑 S4。
- 三道筛选的完整模板见 `references/quickstart.md` §4 与 `references/three-pass-screening.md`；本文件不重复收录。

# 零丢失合并压缩流程（zero-loss merge）

> 适用：对「每行一条记录」的清单式合并稿做二次压缩，并在压缩前后**证明硬数据零丢失**。
> 前置：母本已定稿（追加式抽取 + 严格去重已完成）。本流程只做「删冗余重述行 / 切卷 / 校验」，不再改写任何一个字。
> 红线：硬数据（数值 / 单位 / 编号 / 版本号 / 冲突标记 / 规则级条款）一个不许丢；文字可压，数字不可压。
> 与既有文档分工：切块、自生专注力、重叠、统一整理、元总结、二次查漏见 `guide/red-lines.md` 与 `summarization-methodology.md`（其 2.7.1 已有「数字零遗漏」原则）；本文把该原则下沉为**可执行、可脚本化、可追溯**的一段细则，不重复原则论述。
> 不确定口径标 `(待核)`，不编造。全程严格串行，不启动其他 agent。

---

## 0. 总流程（串行，勿并行）

| 步 | 动作 | 产物 | 硬校验 |
|---|---|---|---|
| 1 | 切块/删除**之前**建硬数据指纹基线 | `硬数据指纹_基线.json` | 三类指纹非空、锚定最原始母本 |
| 2 | 程序化行选择合并（AUTH/CAND + Pass2 救回） | 合并稿 + `_merge_state.json` | 逐块回跑指纹，丢任一硬 token 即回退 |
| 3 | 按行切分成卷（二进制） | N 个卷文件 | `assert b''.join(vols) == raw` |
| 4 | 生成逐行去向映射文档（输出文档之外） | `*_行映射_二压.md` | L1–L末全覆盖、无 `输出LNone` |
| 5 | 零丢失集合层比对 | 差集报告 | `set(base)-set(out) == ∅`（仅种类） |
| 6 | 零丢失下限判定 | 停止/继续结论 | 双阈值触发即停 |
| 7 | 内容筛选（见 `three-pass-screening.md`） | 定稿 | 剔除∪放回=初判全集且互斥 |
| 8 | 交付前端到端清单全过 | 交付 | 见 §7 |

本地脚本不算 agent，可与下一步串行衔接；任何时刻只 1 个 agent 在跑。

## 1. 硬数据指纹基线（切块前生成）

### 1.1 三类指纹抽取口径

| 类别 | 正则 | 抽取要点 | 本轮数量 |
|---|---|---|---|
| 设计点编号 | `[a-z]{2}-\d{3}` | 用 `\b[a-z]{2}-\d{3}\b` 全局抓一遍；再用 `^[a-z]{2}-\d{3} ` 补抓「行首零填充条款」，取并集 | 480 |
| 数值 + 单位 | 见下方 `NUM_PATS` | 版本号必须整体优先；裸数值最后取，且须剔除子串噪声（§2.2） | 1493 条（含重复，独种 454）(待核：1493→454 为不同抽取器口径) |
| 冲突标记 | `【冲突[：:][^】]*】` | 全角/半角冒号都收；`⚠️冲突` / `并存\d+` / `J\d+` 等编号化 registry 作补充口径 (待核) | 18 (待核：另处记 19 / 36，阶段口径差异) |

`NUM_PATS` 代表性实现（单位词表需按目标文档扩充 `(待核)`）：

```python
NUM_PATS = [
    r'\d+(?:\.\d+)+',                                   # 版本号/小数，必须首项、整体优先
    r'\d{1,3}(?:,\d{3})+(?:\.\d+)?',                   # 千位逗号
    r'\d+(?:\.\d+)?\s*(?:%|％|‰|倍|格|秒|分钟|小时|天|'
    r'KB|MB|GB|B|字节|字|度|℃|px|ms|token|积分|层|级|次|个|条|点|'
    r'米|cm|mm|kg|g|L|ml)',                             # 数值 + 单位
    r'\d+(?:\.\d+)?\s*[-~～]\s*\d+(?:\.\d+)?',         # 范围
    r'\d+(?:\.\d+)?',                                   # 裸数值（末位，需过噪声过滤）
]
```

> 首项 `\d+(?:\.\d+)+` 是关键：否则 `1.21.1` 会被拆成 `1.21` / `21` / `1` 三个伪值，制造假丢失/假覆盖（troubleshooting 第 22 项）。

### 1.2 基线 JSON 结构

```json
{
  "source": "合并总结_压缩.txt",
  "source_bytes": 711656,
  "source_lines": 2034,
  "generated_at": "切块前·任何删除前",
  "nums": ["aa-001", "ab-002"],
  "vals": ["6.25%", "2048", "1.21.1", "6.25%"],
  "conf": ["【冲突：源稿矛盾】"]
}
```

- `nums = sorted(set(设计点编号))`；`conf` 为冲突标记列表；`vals` 抽取**含重复**（本轮 1493 条），比对前统一 `set()` 得独种（本轮 454）。
- 三类均 `sorted()` 落盘，保证可复现、可 diff。
- 基线文件由 `build_fingerprint.py` 生成；生成后即**只读**，压缩/切卷/筛选全程不得改写。

### 1.3 生成时机（硬性）

必须在**任何切块、任何删除、任何改写之前**，锚定最原始母本生成。原因：切卷、行选择、内容筛选都会改变文本，若基线取自中间态，则「零丢失」退化为「相对中间态不丢」，无法证明相对原始母本不丢。基线是全流程单一事实源。

## 2. 零丢失比对口径：种类覆盖 vs 计数覆盖

### 2.1 只报种类差集

```
missing = sorted(set(base_vals) - set(out_vals))
assert not missing
```

- **唯一合法口径 = 集合层种类覆盖**：`set(base) - set(out)`，只报「种类差集」。
- **重复出现次数下降不算丢失**：合并同类项、删冗余重述本就合理（同一数值在原文出现 20 次、终稿出现 1 次，仍算覆盖）。
- **严禁用多重集比对**：`Counter(base_vals)` 会因次数下降误报大量假丢失（troubleshooting 第 8 项）。基线 `vals` 虽含重复，比对前必须 `set()`。

### 2.2 比对前规整（否则全是伪值）

| 规整项 | 处理 |
|---|---|
| 全角/半角 | `％`→`%`、`－`→`-`、全角数字→ASCII 数字；否则内容其实在、ASCII 正则不匹配 |
| 千位逗号 | `1,234`→`1234`、`3,845,092`→`3845092` |
| 大数字子串噪声 | 按「最长匹配」取完整 token：`6%` 是 `6.25%` 的子串、`8%` 是 `28%` 的子串，短串**不单独登记**，否则误报种类缺失 |
| 版本号整体 | 见 §1.1 首项正则 |

### 2.3 噪声排除清单（差集回原文定位后程序定性）

| 噪声 | 特征 | 处置 |
|---|---|---|
| 图片 CDN 哈希 | 长十六进制 / base64 串 | 移出差集，不计丢失 |
| `auth_key` | 带 `auth_key=` / token 串 | 同上 |
| 13 位时间戳 | `^\d{13}$` | 同上 |
| 纯章节序号 | `第N章` / `1.2.3` 层级号 | 同上 |
| 页码 / 纯分隔符行 | `— 12 —` / `━━━` | 同上 |

规则：差集每一条先 `Grep` 回原文定位、再由程序按上表定性；命中即移出，不补、不改原文。剩余才进补漏清单。

### 2.4 差集处置闭环

差集 → Grep 回原文定位 → 生成 `*_补漏清单.md`（原文有、终稿无的硬数据 + 原文上下文）→ 补回对应行 → 复跑集合比对 → `480/480`、`18/18`、`454/454` 全绿才允许进入交付。**种类差集非空时禁止交付。**

## 3. 程序化行选择合并（零改写）

### 3.1 为什么不用手写 / 模型重写

- 一次性 `Write` 巨量内容会触发 `400 prompt too long: 100001>100000`（troubleshooting 第 11 项）。
- 模型复写必然产生**语义漂移**，直接违反「只允许增添和删除已合并内容，绝不改写/重写」红线。
- 程序化行选择：Python 脚本按行号决定 `KEEP` 或 `DEL`，输出 = 被选行**原样拼接**。不经过模型、不重打一个字 ⇒ 零改写、可逐字节验证、天然绕开 Write token 上限。

### 3.2 AUTH / CAND 分区策略

| 区 | 识别特征 | 处置 |
|---|---|---|
| AUTH（权威，全保留） | `###` 段、顶层 `#`、所有 `【…】` 标题、L1343+ 零散内容块 | **整行原样保留**，不参与删减判定 |
| CAND（候选，条件保留） | `**N.` 章节段、`【合并块】`、summary 块 | 仅当该行携带 AUTH 中**缺失的硬 token**（编号 / 冲突 / 数值）或窄规则关键词时才留；否则整行丢弃 |

判据补充：`【xx】` 编号块一律原样保留；章节/合并块所有带数值、冲突、规则的独有事实全留，只删「逐字重复的纯重述句」（troubleshooting 第 9 项：曾误删致丢 57 数值 + 1 冲突，设计点 122/122 全保）。

### 3.3 Pass2 救回

对 Pass1 被 `DEL` 的行再跑一遍宽松复核：计算该行与「当前输出」的 **3-gram 重叠**；若**零重叠**（说明含独有概念、无硬 token 可依赖，如「天然五行反应场」），则**强制保留**。目的：兜住「无数值/无编号但语义独有」的行，防过度删。救回后仍须回跑指纹校验。

### 3.4 `_merge_state.json`：单一事实源

```json
{
  "mapping": [[1, "KEEP", 1], [2, "DEL", null], [3, "DEL_REDUNDANT", null]],
  "scatter_start": 1343
}
```

- `mapping=[(src, status, out_ln)]`：`src` = 母本物理行号；`status` ∈ `{KEEP, DEL, DEL_REDUNDANT}`；`out_ln` = 输出行号，被删行为 `null`。
- **`status` 常量必须与行映射/校验脚本完全一致**：外层判 `('DEL','DEL_REDUNDANT')`、内层「合并连续删除」循环若只认 `'DEL_REDUNDANT'`，遇 `'DEL'` 行 `j` 不前进 → SIGTERM 死循环（troubleshooting 第 7 项）。
- 它是合并程序、行映射文档（§5）、零丢失校验三者的单一事实源，不得各写一份。
- 迭代纪律：每版（v4→v6→v8→v9）都跑指纹校验，任一硬 token 丢失即回退修正，不带着丢数据往下走。

## 4. 按行切分与字节一致校验

### 4.1 二进制模式脚本骨架

```python
src = "合并总结_压缩.txt"
raw = open(src, 'rb').read()                 # rb：绝不触发换行翻译
lines = raw.splitlines(keepends=True)        # 保留 \r\n / \n 原样，不丢行尾
# 切分点严格落在 lines[i] 与 lines[i+1] 之间，绝不切断行
ranges = [(0, 277), (277, 507), (508, 861)] # 示例：行号区间 [a, b)
vols = [b''.join(lines[a:b]) for a, b in ranges]
assert b''.join(vols) == raw                # 逐字节相等，硬门槛
```

### 4.2 三条硬约束

1. 读写一律 `'rb'` / `'wb'`，或显式 `newline=''` + `encoding='utf-8'`；**禁止依赖 Windows 文本模式默认换行转换**。
2. `splitlines(keepends=True)` 保留行尾；拼接用 `b''.join`，不用文本 `''.join` 后再编码。
3. 切分点可优先吸附空行 / `【区块】` 标记，但必须**严格两行之间**；字节阈值参考 `total*(k+1)//N`，吸附后仍需满足 `assert joined == raw`。

### 4.3 Windows 文本模式 CRLF→LF 陷阱

- 现象：文本模式 `open(...,'r')` 把 `\r\n` 悄悄翻成 `\n`，拼接体积与原稿不符，`重建==源 False`。
- 判据：拼接后字节数 < 源字节数，且差值 ≈ 行数（每个 `\r` 少 1 字节）⇒ 几乎必是 CRLF 翻译。
- 修复：改二进制模式重跑，`重建==源 True`（逐字节相等）。详见 troubleshooting 第 1 项。

## 5. 逐行去向映射文档

### 5.1 硬要求

- 输入 `L` → 输出 `L` 一一映射；**多行对一行时全部指向同一输出行**。
- **连续删除合并为区间**并注明删除原因（如「与 O0098 逐字重复」）。
- 源行 `L1–L末` **全覆盖**，无 `输出LNone` 残留、无遗漏、无重叠。
- **必须放在输出文档之外单独存放**（如 `合并总结_行映射_二压.md`），绝不写进合并稿正文，否则污染定稿、破坏字节一致性（B-R7）。

### 5.2 格式示例

```
L0001 -> O0001   [KEEP]  ### 来源骨架
L0002 -> O0002   [KEEP]
L0130-L0134 -> O0118   [DEL_REDUNDANT] 与 O0098 逐字重复
L0500 -> (删除)  [DEL] 纯分隔符行
```

### 5.3 覆盖断言骨架

```python
covered = {}
for a, b, out_ln, reason in mapping_rows:      # 来自 _merge_state.json
    for ln in range(a, b + 1):
        assert ln not in covered, "重复覆盖"
        covered[ln] = (out_ln, reason)
assert set(covered) == set(range(1, len(lines) + 1)), "存在未覆盖源行"
assert all(v[0] is not None or v[1] for v in covered.values()), "存在无原因删除"
```

## 6. 零丢失下限判定与停止压缩

### 6.1 不可再压缩原子（零丢失红线，禁止删）

- 硬数据：数值 / 单位 / 编号 / 版本号 / 公式 / 坐标 / 配比 / 阈值 / 时长 / 概率 / 百分比 / 尺寸 / 层级 / 字节计数。
- 冲突标记：`【冲突：源稿矛盾】` 及多值并列（绝不二选一）。
- 规则级条款、关键原话、文档骨架（`###` / `【…】` / `- ` / 来源标注）。

### 6.2 数学论证

当文档已由上述原子构成——每条独立成行、无冗余修饰、无重复陈述、无寒暄填充——可压空间趋于 0，压缩比 → 1。此时任何进一步压缩都只能删「独有原子」，直接违反零丢失红线，故**存在不可压缩下限**。本轮构成：147 KB `###` core + 345 KB 零散 L1343+ 独有块 + 27 KB 独有硬数据行 ⇒ 519 KB 为下限（`<500 KB 数学上不可能` 为估算 `(待核)`）。

### 6.3 双阈值停止判据

每轮记录 `(输入字节, 输出字节, 压缩比)`，任一命中即**立即停止**：

| 判据 | 阈值 |
|---|---|
| 压缩比 | `≥ 0.9`（压不动） |
| 输出 vs 输入 | `输出字节 ≥ 输入字节` |
| 连续无下降 | 连续 `N`（建议 3）轮压缩比无下降 |

二压实证：705 → 705.9 KB 几乎无效；压缩比样本 0.9909 / 0.9015 / 0.880。(待核：样本来自不同批次)

### 6.4 向用户报告（固定话术）

> 「已达零丢失下限，继续压必然丢数据。」

把选择权交用户；**禁止为凑篇幅强压**。二压判为岔路废弃、合并文档即最终输出，不再进主链。

## 7. 交付前端到端校验清单（逐条过，全绿才交付）

1. `硬数据指纹_基线.json` 存在，且生成于任何删除之前、锚定最原始母本。
2. 合并稿由程序化行选择产出，无手写/模型重写痕迹（可逐行回溯到母本）。
3. `_merge_state.json` 的 `mapping` 覆盖 L1–L末，`status` 常量与校验脚本一致。
4. `assert b''.join(vols) == raw` 通过（二进制逐字节相等）。
5. 切分点全部严格两行之间，无半字符/半行切断。
6. 逐行去向映射文档在输出之外、覆盖完整、连续删除已合并为区间并注明原因、无 `输出LNone`。
7. 集合层比对 `set(base)-set(out) == ∅`：`nums` / `conf` / `vals` 三类全绿。
8. 差集噪声已按 §2.3 程序定性排除，补漏清单为空。
9. 已过停止判据；若曾触发，已向用户报告「已达零丢失下限」。
10. 交付命名、目录、格式符合 `guide/tools-ops.md`「交付与清理」，终稿与输入同根目录。

## 7·补 零散内容块自动探测（防成片误删，硬性）

源文档里成片的「零散独有内容」常只靠一行同源标记统领，例如
`【来源：…零散内容设计.txt】（本块全条同源，仅标此一次）`。
**用户漏传 `--scatter-marker` 会让这一整片被判为 CAND 而误删**：

| 情形 | 输出字节 | 说明 |
|---|---|---|
| 显式 `--scatter-marker` | 全保 | 零散块正确划入 AUTH，全保 |
| 不传 marker，**开启自动探测**（默认） | 结果一致 | 自动识别同源标记，结果一致 |
| 不传 marker 且 `--no-auto-scatter` | 明显缩水 | 丢大量独有纯文字概念 |

**危险点**：这类误删**数字指纹查不出来**（丢的是「桌宠 / 冰芯 / 权重加密 / 天然五行反应场」
这类纯文字概念，不含编号/数值/冲突标记），三类指纹仍显示「零丢失」。
因此「指纹零丢失」**不等于**「内容零丢失」，必须配合剔除行内容体检与零散块分区核对。

- 未指定 marker 时自动探测标题行中的 `本块全条同源` / `仅标此一次` / `零散内容` / `本块同源`；
- `--no-auto-scatter` 显式关闭；运行时必须打印「零散起点：L…」；
- 显示「未分区」且源文档确有成片独有内容时，显式指定 marker 重跑；
- 同理，**Pass2 零 3-gram 救回**是第二道语义网，两者不可互相替代。

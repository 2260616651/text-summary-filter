# 三道串行内容筛选协议（three-pass screening）

> 适用：**执行顺序已按权威流程真反转：筛选(第2步)→合并(第3步)**。三道筛选在编排器里**先于**条目合并执行，基于「筛选基准稿」（第 1 步总提取稿经 `init --extract` 入链，不给则退回母本）按行剔除与主题无关的工程残留 / 纯空白行，筛选结果再由第 3 步条目合并（S2）按 `final_remove_lines` 落盘，且必须保证零误删。旧「先合并后筛选」链已废弃。
> 目的：**防误删，宁可多留不可错删**。用三道独立 agent + 阈值梯度 + 输入依赖收敛，把「误伤」限制在可捞回范围内，再以集合硬校验兜底。
> 红线：整行保留不拆行、原文零改写（二者为默认保真手段，目标为信息不丢；允许在信息不漏前提下改写／合并／丢闲笔）、拿不准→放回、硬数据指纹零丢失。
> 不确定口径标 `(待核)`，不编造。全程严格串行，不启动其他 agent。

---

## 1. 适用场景与前置条件

| 项 | 要求 |
|---|---|
| 输入母本 | 一份「每行一条记录」的定稿文本（行数与体积以本次输入为准），行号体系已固定 |
| 判定对象 | 单一明确主题（如某整合包设定），须在判定基准里**写死定义** |
| 前置产物 | 筛选基准稿（`init --extract`，不给则退回母本）、硬数据指纹基线（锚筛选基准稿）、统一判定基准、判定视图；`_merge_state.json` 仅在 `--legacy-merge` 时产生 |
| 不做的事 | 不改写字、不合并行、不重排、不补写、不引入母本外信息 |

触发信号：母本里混有区块/分卷标记、来源文件名标注、合并块标题、行映射说明、压缩/去重/切分/指纹记录、纯空白行、分隔符、页码等**纯文档工程残留**，需剔除但不许碰任何一条设计点。

## 2. 准备三件（缺一不可）

| # | 产物 | 作用 |
|---|---|---|
| ① | `筛选_判定基准.md` | 三道 agent **唯一共用标准**，必须完整读完，不许各判各的 |

| ③ | 原文抽取脚本 | 按行号从母本逐字节抽取生成新文档，**零改写**（`build_line_view.py` / 抽取脚本） |

## 3. 统一判定基准模板（五节结构，可直接复制）

三道 agent 提示词都必须内联或指向**同一份** `筛选_判定基准.md`，并强制「先完整读完再动手」。模板固定五节：

```text
【第一节 · 判定对象定义 + 应保留类别清单】
判定对象：{主题名，如某整合包设定}。
「有关联」包含但不限于：直接设定、间接设定、素材、背景、工具链、开发流程解释、
灵感来源、可据以推导设计的信息、能统领下方成片设计的骨架行。
以上类别一律保留，即便信息量很低。

【第二节 · 「毫无关联」唯一可剔除标准（三条须同时满足）】
仅当一行同时满足以下三条，才可判为剔除候选：
  (1) 不含任何主题 / MC / 整合包实质信息；
  (2) 不能作为设计依据 / 素材 / 背景 / 工具链 / 开发流程解释；
  (3) 属其他项目，或纯文档工程残留（区块/分卷标记、来源文件名标注、合并块标题、
      行映射说明、压缩/去重/切分/指纹校验记录、纯空白行、分隔符、页码）。
补充铁律：
  - 边界模糊一律不得剔除；拿不准 → 放回；
  - 整行保留不拆行：一行只要夹带任何主题设计信息，整行留；
  - 文档骨架一律保留：章节标题、### 小标题、【…】分组标记、- 起始符、来源标注。

【第三节 · 三道分工与阈值表】
  第 1 道 宽松初筛：疑似无关就拎出，允许误伤 → 文档 A
  第 2 道 极宽松抢救：仅输入 A，任何关联线索一律捞出，宁可错捞不可漏 → 文档 B
  第 3 道 终审：拿不准 → 放回，可否决前两道 → 文档 C（放回集 / 剔除集）
  阈值梯度 = 宽 → 极宽 → 终审；后道只在前道输出范围内工作。

【第四节 · 输出硬性要求】
  - 只输出「行号 + 理由」，不输出正文、不复写原文；
  - 行号 = 母本物理行号（与判定视图 L<n> 一一对应）；
  - 每条必须附 reason；
  - 输出 UTF-8 JSON 行号清单，写入前须过只读校验（见协议 §6）；
  - 只做自己那一道，不越权处理别的道次。

【第五节 · 零丢失底线】
  - 硬数据（数值/单位/编号/版本号/冲突标记/规则级条款）零丢失；
  - 设计条目删 0 句；
  - 剔除集 ∪ 放回集 = 初判全集且互斥；
  - 定稿与母本（删剔除集后）逐字节一致（默认保真手段的校验；若改用改写／合并式压缩则以「信息可定位」为达标判据）；
  - 任一不满足即判本道失败，回退重跑，不得放行。
```

## 4. 判定视图生成

### 4.1 格式

```
L0001| 首 55 字……尾 20 字
L0002| 首 55 字……尾 20 字
```

- 每行一条，`L{n}|` 前缀与母本物理行号严格对应（1-based）。
- 截「首 55 字 + 尾 20 字」：既给开头语义、又给结尾落点，避免只看开头误判「统领下方成片设计」的骨架行。
- 目的：让 agent 在有限上下文里**通读全量行**（本轮 1318 行），而非只抽样。

### 4.2 生成脚本骨架（二进制读，零改写母本）

```python
raw = open(master, 'rb').read()
lines = raw.splitlines(keepends=False)
with open(view, 'w', encoding='utf-8') as f:
    for i, ln in enumerate(lines, 1):
        s = ln.decode('utf-8', errors='replace')
        head = s[:55]
        tail = s[-20:] if len(s) > 75 else ''
        f.write(f"L{i:04d}| {head}" + (f"…{tail}" if tail else '') + "\n")
```

### 4.3 回查规则（硬性）

视图只是索引，**拿不准必须按行号回查母本完整原文**，用 `Read` 的 `offset/limit` 读 `[L, L+若干]` 区间，`islice(f, L-1, L)` 亦可。**严禁凭截首臆断**。母本可能有 CRLF/BOM，回查同样用二进制或 `newline=''`（见 troubleshooting）。

## 5. 三道阈值梯度与输入依赖（严格串行）

| 道次 | 角色 | 输入 | 阈值 | 输出 | 本轮条数 |
|---|---|---|---|---|---|
| 第 1 道 | 宽松初筛 | 母本全量（判定视图 + 可回查原文） | 疑似无关就拎出，**允许误伤** | 文档 A `筛选1_初判无关条目.md` | 90（80 纯空白行 + 10 文档工程残留） |
| 第 2 道 | 极宽松抢救 | **仅**文档 A | 任何关联线索一律捞出，**宁可错捞不可漏** | 文档 B `筛选2_复核关联条目.md` | 9 |
| 第 3 道 | 终审 | 文档 A + 文档 B | **拿不准→放回**，可否决前两道 | 文档 C `筛选3_终审判定.md` | 放回 9 / 剔除 81（80 空行 + L3 分隔符） |

### 5.1 第 1 道 · 宽松初筛

- 输入母本全量，逐行过判定基准第二节。疑似无关即拎出，允许误伤（误伤由后两道捞回）。
- 输出文档 A 的 JSON 行号清单。
- **主线程额外独立抽查**（见 §9）：是否漏拎大块无关内容。漏掉的第 2、3 道救不回。

### 5.2 第 2 道 · 极宽松抢救（输入依赖收敛的关键）

- **仅**输入文档 A；**不重读母本全文、不引入 A 之外的新条目**（否则漏斗失效）。
- 对 A 内每条回查**母本上下文**（该行及其下方若干行），判断「是否统领下方成片设计」——骨架行即使自身信息量低，只要领起成片设计就捞回。
- 任何关联线索（间接 / 素材 / 背景 / 工具 / 灵感）一律捞出，宁可错捞不可漏。
- 输出文档 B，必须满足 `B ⊆ A`。

### 5.3 第 3 道 · 终审（可否决前两道）

- 输入 A + B，**拿不准 → 放回**（零丢失是硬底线）。
- **逐条独立回查**母本原文，不沿用前两道结论；可否决前两道任一判别。
- 须**覆盖 B 每一条**（逐条给出放回/剔除结论），并**复核 A 剩余**条目。
- 输出两个互不相交的集合：放回集、剔除集；二者并集恰为 A。
- 本道曾被中断，重跑前须先查有无残留 JSON（见 §10）。

## 6. JSON 行号清单协议

### 6.1 Schema

```json
{"items": [{"line": 123, "reason": "纯空白行，无主题信息", "verdict": "剔除"}]}
```

- `line`：母本**物理行号**（1-based，与 `L<n>|` 一一对应）。
- `reason`：非空，说明依据判定基准哪一条。
- `verdict`：本道结论（第 1/2 道可用「初判无关 / 捞回」，第 3 道用「放回 / 剔除」）。
- 每道写独立文件 `agentN_result.json`，UTF-8，互不覆盖。

### 6.2 写入前的只读校验（不通过不落盘）

校验脚本**只读**，在 agent 真正 Write 之前跑；任一失败即打回重出，不写入半截结果：

| 校验项 | 判据 |
|---|---|
| 结构 | `items` 为数组；每条含 `line`(int) / `reason`(str) / `verdict`(str) |
| 唯一 | `line` 无重复 |
| 升序 | `line` 严格递增 |
| 无越界 | `1 ≤ line ≤ 母本总行数` |
| 理由 | `reason.strip()` 非空 |
| 子集（第 2 道） | `set(B) ⊆ set(A)` |
| 互斥 + 完备（第 3 道） | 放回集 ∩ 剔除集 = ∅；放回集 ∪ 剔除集 = `set(A)` |
| 对应 | 每个 `line` 能在判定视图找到 `L{n}\|` 前缀 |

```python
import json
d = json.load(open(path, encoding='utf-8'))
ls = [x['line'] for x in d['items']]
assert ls == sorted(set(ls)), "行号须唯一且升序"
assert all(1 <= n <= total for n in ls), "行号越界"
assert all(str(x.get('reason','')).strip() for x in d['items']), "reason 不得为空"
```

## 7. 原文零改写抽取

- agent **只给行号 + 理由**，绝不输出正文；原文一律由脚本按物理行号从母本 `splitlines` **逐字节抽取**生成新文档。
- 严禁手工复写 / 缩略 / 截断 / 改标点 / 合并行。抽取脚本与生成判定视图用同一套二进制读取逻辑，保证行号与字节对齐。

```python
raw = open(master, 'rb').read()
lines = raw.splitlines(keepends=True)
keep = set(放回集)                       # 或 全集 - 剔除集
out = b''.join(lines[i-1] for i in sorted(keep))
open(final, 'wb').write(out)             # wb：不触发 CRLF 翻译
```

> 定稿生成后仍需与「母本删去剔除集」逐字节比对（§8），证明零改写。

## 8. 终局集合硬校验（四条断言，全绿才交付）

```python
A = set(文档A行号); B = set(文档B行号)
back = set(放回集); drop = set(剔除集)
assert (drop | back) == A, "剔除∪放回 ≠ 初判全集"
assert not (drop & back), "剔除集与放回集不互斥"
assert all(1 <= n <= total for n in drop | back), "行号越界"
assert open(final,'rb').read() == b''.join(
        lines[i-1] for i in sorted(set(range(1,total+1)) - drop)
       ), "定稿与母本逐字节不一致"
```

| # | 断言 | 失败含义 |
|---|---|---|
| 1 | 剔除集 ∪ 放回集 = 初判全集 A 且互斥 | 有条目被漏判或重复判 |
| 2 | 行号无越界 | 行号体系错位（0/1-based 混淆，见 troubleshooting 第 12 项） |
| 3 | 定稿与母本（删剔除集后）逐字节一致 | 发生了手工改写/CRLF 翻译/截断 |
| 4 | 硬数据指纹零丢失（`480/480`、`18/18`、`454/454`） | 误删了带硬数据的设计行 |

四条全绿 + 设计条目删 0 句 → 生成 `筛选_汇总报告.md`，进入交付。

## 9. 额外独立抽查（主线程，必做）

第 2、3 道**只能复核文档 A 内的条目**：第 1 道若漏拎「大块无关内容」，后两道结构上救不回。故主线程须在第 1 道完成后、启动第 2 道之前，独立抽查：

- 用关键词 / 结构标记在母本扫一遍，确认没有成片的工程残留、来源文件名列表、行映射说明块被整段漏拎。
- 抽查结论记入汇总报告；若发现漏拎，把漏掉的行号**补进文档 A** 再继续（此时 A 变大，第 2 道输入随之更新）。
- 该抽查由主线程做，不新起 agent，不违反「一次只 1 个 agent」。

## 10. 执行纪律（硬性）

| 项 | 要求 |
|---|---|
| 串行 | 三道**严格串行**，跑完一道再起下一道；一次只 1 个 agent，**不启动任何其他 agent** |
| 前台 | **必须前台跑**；后台 agent 在本环境易被 killed / 零产出（试 3 次均回收），不可依赖、不再重试 |
| 唯一基准 | 三道共用同一 `筛选_判定基准.md`，且必须完整读完；不许各判各的 |
| 各守其道 | 每道只做自己那一道，不越权、不重读母本全文（第 2 道）、不引入新条目 |
| 只回一行 | 每道 agent 只回一行确认（如 `done N M`），**不回正文**；块内容/判定正文零回流主线程 |
| 中断恢复 | 被中断后**先查残留文件与 JSON** 再下结论；只补缺失区间、不整批重跑；重跑加**防重复写入保护**；先判「已产出/部分产出/零产出」再动作 |
| 压缩比异常 | 产出压缩比异常（如 16:1）即判不完整，先查残留再补跑 |
| 本地脚本 | 只读校验脚本、抽取脚本不算 agent，可与下一道串行衔接 |

> 「先查文件系统再下结论」是恢复总原则：框架报 `failed` / 超时 / 429 / 后台零产出时，先 `ls` / `wc -l` / 查输出文件是否已写完，实测有「failed 但文件其实已完整写完」的情况，补一条 `cat` 即零成本复活（见 troubleshooting 第 15/16 项）。

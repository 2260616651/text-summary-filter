## 合并规格

> **新 7 步归属**：本文件「零丢失压缩与合并 / 多文档机械合并」对应权威流程**第 3 步「条目合并」**（去重／合并互补／冲突四选一裁决／统一整理／全局摘要＋每块要点）；它同时是**复压与补漏回流的统一回跳点**——任何需要重跑的场景（第 5 步补遗漏／第 7 步体积不达标）都回跳到条目合并，把上一轮输出当输入接着跑（允许逐条简化、不碰红线），绝不写成「先合并后筛选再来一轮」。⓿ 前置的「多源机械合并成母本」不计入 7 步编号。**执行顺序已按权威流程真反转：筛选(第2步)→合并(第3步)**：编排器 S2（条目合并）在筛选链之后执行，按终审 `final_remove_lines` 从筛选基准稿整行落盘；**语义合并（合并语义相近/同类事物语句 + 不丢信息地简化描述）已由第二批真实现**（`scripts/merge_semantic.py`：候选簇机械生成 → 1 个前台 agent 裁决 → 全覆盖+数字指纹零丢失硬校验 → 落盘，详见本节末「第 3 步真语义合并」）。

### 多文档合并总结 + 机械合并/递归重切（多份源再总结）

机械合并（硬拼接）：要把 N 份源文档（如 24 篇终稿、或多份已浓缩稿）先拼成一份母本时，用 `scripts/merge_and_chunk.py --inputs <文件…>` 做机械首尾连接——每份前插入硬边界标记 `### 来源文件：<名> ###`（仅作溯源锚点，不计入总结内容），不加任何过渡润色。连接产物即母本，后续喂 `split_document.py` 切块、再走标准流程或第一层综合。

递归重切（总总结也要切分）：若最终产出的总总结本身仍过大（超单批次上下文），绝不能"一次性吐总结"——要把它再次切分 → 分别生成缩略文档 → 再合成一起供参考，即把总总结当作一份新的待总结源文档重跑"切块 + 逐块摘要 + 合成"，形成可递归收敛的环路。机械拼接与切块统一由 `merge_and_chunk.py` 承担（复用 `split_document.py` 的等宽/重叠/不切断行逻辑）。

当要综合的是已浓缩的摘要稿（而非完整终稿）时，改用「第一层综合」专用模式（见下），禁用普通 merge 流。

### 第一层综合（多源浓缩稿专用合成模式，非普通 merge 流）

当要把 N 份已浓缩的摘要稿（doc-extract-filter 产出的 `group_*.md` 缩略档、或任何多级总结的中间稿）再综合成「批次稿 + 总总结」时，用本模式。用户硬规定：最后的总结不能用普通流程、禁用普通子 Agent merge 流。

- 方法（用户原话落地）：
  1. 分段以简短的话概括；
  2. 检查重复和冲突；
  3. 完全重复（是否重复要看它的描述）→ 批准删除多余文本、指回前文（"同上 / 见批次 X 第 Y 节"），不重写；
  4. 大致重复（互补或重叠但各自携带不同信息）→ 不许删任何一个，全部保留（即便文字相近）；
  5. 冲突要标出（编号化 registry，见「追加与统一整理·冲突裁决」）。
- 在主线程做、不用普通子 Agent 合并：涉及"完全/大致重复"判断与冲突标记，需主线程/人把控；综合对象已是浓缩稿、体积可控，主线程自处理不超窗。
- 只做去重/冲突标记、不编造：综合结果必须锚定原始母本（见红线 11）；批次稿/总总结里引用的数值、设定必须能从原始母本 grep 追到。

缩略档仅参考、禁止当作合成依据（红线 11 的落地）：本模式虽以缩略档为综合素材，但缩略档绝不许当原文——凡是准备落进综合稿的事实/数字，必须回原始母本核实（grep 验证存在），缩略档只用于定位"去原始母本哪一段查"。综合阶段只去重、只标记冲突，绝不凭缩略档脑补设定。

### 零丢失压缩与合并（实战沉淀 2026-11）

本节为零丢失压缩与合并的主线索引，全部细则、脚本骨架、实证校准样例见 `references/zero-loss-merge.md`；执行严格串行、勿并行。

- 硬数据指纹基线（切块前生成，硬性）：切块／压缩之前先落盘基线 JSON，抽三类指纹——①设计点编号（如 `[a-z]{2}-\d{3}`）②数值＋单位 ③冲突标记（如 `【冲突：源稿矛盾】`）。基线是后续所有「有没有丢」的唯一底线，切块后不再重建。对应 `fingerprint.py --source … --out 基线.json`。
- 种类覆盖 vs 计数覆盖（比对口径，硬性）：只比对「种类」是否至少出现一次，只报种类差集、忽略次数下降——原文重复出现的同一数字，终稿合并同类项导致次数减少不算漏；切勿用多重集（`Counter`）比对，否则删重述句就误报「丢失」。比对前先规整全角／半角（全角 `％`→`%`、全角数字→半角），差集回原文定位后程序定性排除噪声（图片 CDN 哈希、auth_key、13 位时间戳、纯章节序号、大数字子串），再生成补漏清单逐个补回。
- **程序化行选择合并（零改写，硬性）**：清单式「每行一条记录」文档不用手写、不用模型重写（会语义漂移且触发 `400 prompt too long`），改由脚本按行号选择「整行原样保留或整行丢弃」。分区策略：AUTH 区（`###` 段、顶层 `#`、所有 `【…】` 标题、零散独有块）一律全保；CAND 区（`**N.` 章节段、`【合并块】`、summary 块）仅当携带 AUTH 缺失的硬 token 或窄规则关键词才留。**Pass2 救回**：被删行若与输出零 3-gram 重叠（如独有概念「天然五行反应场」）则强制放回，捕捉初判漏网。全程状态写入 `_merge_state.json`（`mapping=[(src,status,out_ln)]`、`scatter_start`），作为合并程序、行映射、校验的单一事实源。
- 零散内容块自动探测（防成片误删，硬性）：源文档里成片的「零散独有内容」通常只靠一行同源标记（如「本块全条同源，仅标此一次」）统领，用户漏传 `--scatter-marker` 会让整片被当 CAND 误删——实测某设计文档样本因此丢失大量独有纯文字概念（数字指纹仍显示「零丢失」，因为丢的是纯文字概念）。`line_select_merge.py` 未指定 marker 时自动探测「本块全条同源 / 仅标此一次 / 零散内容 / 本块同源」类标题行并分区；`--no-auto-scatter` 可关闭。运行时必须打印「零散起点：L…」并核对；显示「未分区」且源文档确有成片独有内容时，须显式指定 marker 重跑。
- 按行切分字节一致校验（硬性）：切分／拼接／校验一律二进制模式（`rb` 读 ＋ `splitlines(keepends=True)` ＋ `b''.join` 写）；切点严格落在两行之间，绝不切断行；拼接后必做 `assert joined == raw` 逐字节相等断言。Windows CRLF 陷阱：源若为 `\r\n`，文本模式读写会做 `\r\n`→`\n` 换行翻译，造成假字节差、拼接无法还原，必须用二进制模式并先剥离 BOM。
- 输出文档之外的逐行去向映射（硬性）：单独产出一份映射文档（如 `…_行映射.md`），逐行记录输入 L → 输出 L；多行对一行则都指向同一输出行，连续删除合并为区间并注明删除原因；校验「X 条合并、Y 行全覆盖、无遗漏无重叠、无 `输出LNone` 残留」。该文档必须在输出文档之外，绝不混入正文。
- 零丢失下限判定与停止压缩（硬性）：文档由「不可再压缩原子」（`###` core、零散独有块、独有硬数据行）构成时压缩比趋近 1；设双阈值——压缩比 ≥0.9 或输出 ≥ 输入、且连续数轮无下降，即判定已达零丢失下限，必须停止压缩并向用户报告「不丢独有硬数据下不可再压、继续压必然丢设定／数字」，禁止为凑篇幅强压。实证：二压 705→705.9KB 几乎无效、压缩比 0.9909／0.9015／0.880，故二压判为废弃岔路、合并文档即最终输出。

### 第 3 步真语义合并（第二批实现：`scripts/merge_semantic.py`）

`--semantic-merge on`（`run_pipeline.py init` 默认）时，S2 在按筛选结果落盘「筛后稿」后走真语义合并；脚本只做机械部分、语义裁决只由 **1 个前台 agent** 完成：

- `scripts/merge_semantic.py prepare --input <落盘稿> --outdir <第3步文件夹> --similarity 0.80 --max-cluster 20 --result <合并结果.json> --workdir <目录>`：用 `difflib.SequenceMatcher` + 词元集合 Jaccard（中文按字/双字、英文按词）+ 共享硬数据信号机械生成「语义相近／描述同类事物」候选簇，输出 `合并_候选簇.json` 与 `合并_agent_prompt.md`（完整提示词，只产候选、不裁决）。提示词写明：只处理簇内成员、可合并简化但数字/编号/单位/阈值/百分比/范围一个不许漏、冲突多值全留并标 `【冲突：源稿矛盾】`、文档外推论标「（AI 推论）」、不取一丢一、每个未入簇原始行也必须作为独立 item（全覆盖）、只写自己的 `合并结果.json`、前台串行只回一行确认。
- 主线程**只派 1 个前台 agent**（强锁 1、并发 1、跑完再起下一个、不启动其他 agent、不并发），产出 `合并结果.json`（`{"items":[{"text":"…","sources":[原行号…],"reason":"…"}]}`）。
- `python run_pipeline.py resume --workdir <目录>` 后，S2 自动调 `scripts/merge_semantic.py verify`（全覆盖/无重复引用/行号合法升序/reason 非空/数字·编号·单位指纹零丢失/不得凭空新增硬数据）与 `render`（先跑同一套硬校验，通过才写 `合并稿.md` + `合并_行映射.md`），把校验通过的合并稿写入 `f["merged"]` 供 S7 出终稿。
- `--semantic-merge off` 退回第一批直通（零改写）；`--legacy-merge` 走 `line_select_merge.py` 机械删行/去重。
- 硬校验失败一律非零退出、明确报错、不落盘（漏行号／丢数字／丢单位都能拦住）；可复制命令序列见 `references/quickstart.md` 第 3c 节，已知限制见 `guide/red-lines.md`「当前实现边界」。
